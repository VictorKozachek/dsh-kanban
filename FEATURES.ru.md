# Возможности dsh-kanban

[English version](FEATURES.md) · состояние на 2026-10-30 (main, DSH 0.2.1-rc.3)

**Что это.** Канбан-доска агентских задач в правом сайдбаре DeepSeek Harness.
Состояние задач живёт в `.kanban/tasks/*.md` внутри git-репозитория проекта: доска
читает файлы и показывает их людям, а host-половина плагина следит за ними и сама
рассылает **наряды** агентским сессиям. Так несколько ролей — оркестратор,
исполнители, ревьювер, тестировщик — работают по одной доске, не переписываясь
в чате.

## 1. Доска в GUI (клиентская половина)

- **Таб «Канбан»** в правом сайдбаре, 8 колонок:
  `backlog → todo → in-progress → in-review → testing → ready → merged`
  плюс `blocked`.
- **Карточка** показывает: id, название, роль и владельца (id сессии), значок
  «в ветке» (задача ещё не слита, карточка прочитана из `worktrees/<id>`), расход
  токенов с разбивкой по ролям, заметку, время и спецификацию. Внутри колонки
  карточки сортируются по id; карточка бэклога без владельца подписана
  «не назначено».
- **Панель деталей** по клику: описание задачи, токены по ролям, сессия
  (роль · владелец), `spec`, все комментарии ролей в порядке появления.
- **Человек в цикле:** перетаскивание мышью **только `backlog ↔ todo`** плюс
  кнопки-дубли «→ В работу» / «← В backlog». Вперёд — асайн: карточка получает
  владельца, исполнителю уходит наряд. Назад — только из `todo`, со снятием
  владельца и роли. Остальные колонки двигают только агенты: дроп туда отвечает
  «эту карточку двигают только агенты».
- **Состояния переноса:** «переношу…» на время запроса, после успеха доска
  перечитывается, при отказе — баннер с текстом хоста («все заняты», «карточка в
  статусе …»), без соединения — «канал недоступен».
- **Вторая вкладка «Дочерние доски»** — обзор досок дерева команд (только
  чтение): дерево по путям с отступами, счётчики карточек по статусам (без
  `merged`), карточки «в работе» с владельцем/ролью и временем обновления,
  ошибка чтения доски — отдельной строкой; клик по доске открывает её колонки,
  клик по карточке — детали (описание, токены, роль/владелец, `spec`).
  Обновление — опрос раз в 3 с и ⟳; пустые состояния различаются: манифеста нет
  (подсказка с `bin/board-children.sh`), манифест не разобран, досок нет. Ни
  drag&drop, ни кнопок перевода здесь нет: родитель смотрит, но не управляет.
- **Обновление** — опрос раз в 3 секунды и кнопка ⟳; светлая и тёмная темы;
  макеты доски лежат в `dsh-kanban/docs/` и рисуются из реальной таблицы стилей.

## 2. Сторож доски (host-половина)

- **Наблюдение за досками:** `.kanban/tasks` основного чекаута и доски рабочих
  деревьев (`worktrees/*`, `.worktrees/*`). Копии одной карточки сливаются по
  свежести `updated` (равенство — в пользу дерева), из дерева берётся только
  одноимённая карточка, файл с чужим `id` отбрасывается.
- **Наряды в сессии** (через `sessionController.prompt` в режиме очереди —
  занятая сессия наряд не теряет):
  - возврат `in-review`/`testing`/`ready`/`blocked` → `in-progress` — владельцу
    карточки;
  - карточка в `in-review` — ревьюверу; в `testing` — тестировщику; в `ready` —
    оркестратору;
  - **асайн**: карточка в `todo` с владельцем — исполнителю («тебе назначена #N,
    бери в работу»);
  - **недобор**: в `todo` меньше `minTodo` — оркестратору («пополни из backlog»).
- **Надёжность доставки:** дедупликация по версии карточки
  (`id:status:updated`) и файл состояния; недоставленные наряды запоминаются в
  `.watcher-pending.json` и повторяются при старте профиля; стартовый обход
  объявляет то, что уже ждёт роль или асайна.
- **Роли подхватываются сами** по событию выбора пресета `agent-preset/selected`
  и хранятся пер-доска в `.kanban/.watcher-roles.json` (переживает перезапуск);
  `roles` в строке плагина — ручное переопределение. Роль не «перетекает» между
  досками: захват и доставка проверяют рабочую директорию сессии.
- **`boards` и `roots`:** явные корни проектов или автоматический обход дерева —
  каждая папка с `.kanban/tasks` получает свой сторож, свою карту ролей и свои
  наряды.
- **Командный канал клиент → хост** `kanbanCardActions` (собственный Typert
  remote): `assign`/`unassign` из GUI, запуск `bin/task-assign.sh` без шелла,
  валидация запроса, сериализация асайнов, проверка фактического изменения
  карточки, отмена по выгрузке плагина.
- **Обзор дочерних досок** `kanbanChildren` (Typert remote только для чтения):
  `read` по `{ request: { sessionId } }` читает `.kanban/children.json` из
  каталога сессии, снимает каждую доску (`.kanban/tasks` плюс `worktrees/*`,
  слияние карточек по свежести `updated` — как у сторожа) и отдаёт снимок со
  счётчиками; ошибка одной доски попадает в её `problems`/`missing` и не валит
  остальные; лимиты 200 досок и 2000 карточек, изменяющих аргументов нет.
- **Самолечение пресетов ролей** (issue #1): определения четырёх ролей едут
  вместе с плагином (`dsh-kanban/presets/role-presets.json`) и регистрируются в
  реестре DSH при каждом старте — обновление или сброс профиля больше не
  «снимают» пресеты, а существующие сессии (id пресета в логе) открываются без
  пересоздания. Дубликаты с legacy-строками профиля ловятся и пропускаются;
  `bin/install-presets.sh --takeover` убирает старый блок из профиля.
- **Самопроверка канала** после старта: «видит endpoint» / «не проверено —
  gateway ещё не готов» / «не объявлен», с разными уровнями лога.
- **Graceful shutdown:** dispose через `ctx.effect` закрывает наблюдателей и
  таймеры, отменяет in-flight наряды и дочерние `task-assign.sh`, идемпотентен и
  укладывается в бюджет DSH (5 с) — проверено на реальном Host-процессе.

## 3. Сценарий работы команды (протокол)

- **Роли:** `dispatcher` (оркестратор), `worker`, `reviewer`, `verifier` —
  пресеты агентов, которые поставляет сам плагин (регистрируются при старте,
  id стабильны); права и переходы описаны в `AGENTS.md`.
- **Карточка — единственный источник статуса** (front matter:
  `status`, `owner`, `role`, `spec`, `since`, `tokens`, `tokens_<роль>`, `note`,
  `branch`, `worktree`). Переходы — только через `bin/task-move.sh`, слияние —
  только через `bin/task-commit.sh`.
- **Изоляция на задачу:** `task-new.sh` создаёт `worktrees/<id>`, ветку
  `task/<id>` и карточку внутри ветки. Слияние — `--no-ff` с сообщением
  `[<ID>] …`, после чего рабочее дерево убирается. `git push` — только человек.
- **Очередь и бэклог:** спецификации `.kanban/specs/<NNN>.md` и поле `spec`;
  задачи нарезаются в `backlog` без владельца; `minTodo` — в
  `.kanban/board.json`; пул исполнителей — `.kanban/.workers.json`; выдача —
  `backlog-fill.sh` по FIFO по слитому снимку доски (включая карточки, живущие
  только в ветке); ручной асайн — `task-assign.sh`.
- **Лимиты протокола:** один `in-progress` на агента, не больше трёх задач в
  работе, выдаёт задачи только оркестратор, ревью и тесты возвращают карточку
  тому же исполнителю.

## 4. Инструменты (`bin/`, 21 скрипт)

| Группа | Скрипты |
|---|---|
| Задачи | `task-new` (worktree + ветка + карточка, `--backlog`, `--spec`), `task-move` (переходы с проверкой), `task-commit` (merge и `--no-merge`), `task-assign` (асайн/возврат), `backlog-fill`, `spec-new`, `task-usage` (токены из кэша проекций DSH) |
| Доска | `board-status` (дамп, `--json`), `board-sync` (манифест деревьев вне проекта), `board-children` (манифест дочерних досок: `--root`, `--depth`, `--base`, `--board`, `--print`) |
| Установка | `install-kanban` (профили web/desktop, защита от двойного монтирования), `install-presets`, `gen-role-presets` (пресеты из встроенного `standard`) |
| Качество | `test.sh` (весь набор), `test-scripts.sh` (скрипты, локали, коды возврата), `host-shutdown-check.mjs` (реальный Host: control/board/roots/events), `render-mockup.sh`, `node.sh` |

## 5. Совместимость и надёжность

- Проверено на DSH **0.2.1-rc.3** (ранее 0.1.7) и macOS bash 3.2: пресеты
  перегенерируются из шаблона DSH; скрипты не ломаются под `LANG=C.UTF-8`;
  коды возврата не маскируются; `task-assign` и `backlog-fill` честно отдают
  1/2/3/4.
- Обновление DSH проходит штатно (graceful shutdown); апгрейд переживают бандлы
  профиля, симлинк плагина, карта ролей и `.workers.json`.
- Дедупликация и повторы недоставленных нарядов; проверка фактического
  результата асайна на стороне канала; отмена дочерних процессов при выгрузке.

## 6. Тесты, макеты, документация

- **14 тестовых файлов** и `bin/test-scripts.sh`: **479 проверок** в
  `bin/test.sh` — рендер без браузера, парсер карточек, слияние worktree-копий,
  наряды, обзор деревьев, канал, dispose/shutdown, обзор дочерних досок
  (служба и вкладка), скрипты, локали.
  Отдельно — медленный харнесс настоящего Host-процесса (не входит в набор).
- Макеты в `docs/` рисуются из реальной таблицы стилей `client.js`; проверки
  следят, что таблица файлов в `KANBAN.md` не врёт и не отстаёт от набора.
- Документация: `KANBAN.md` (обзор, установка, сценарии, границы, диагностика),
  `AGENTS.md` (протокол агентов), `.kanban/tasks/README.md` (формат карточки),
  спецификации задач (заводятся `bin/spec-new.sh`; в публичный снапшот репозитория
  карточки и спеки не входят — они остаются локальной историей работы),
  скилы `kanban` и `commit`.

## 7. Границы: чего сейчас нет

- Доска **не пишет** состояние в DSH-storage: источник правды — файлы, поэтому
  обновление идёт опросом (раз в 3 с), без живого стрима.
- Человек двигает только `backlog ↔ todo`; drag-между остальными колонками,
  приоритеты, дедлайны и мобильное DnD не поддерживаются.
- **Дочерние доски — только чтение:** родитель видит сводку дерева и открывает
  доски детей без кнопок и drag&drop, асайн и переходы делает команда дочерней
  доски. Read-only — гарантия службы и UI, а не песочница: если доски детей лежат
  внутри workspace родителя, он физически может писать в них bash'ем; для жёсткой
  изоляции dashboard-воркспейс держат вне дерева детей.
- Набор самодостаточен: внешних копий, зеркал и синхронизации с другими
  проектами нет — этот репозиторий единственный источник. `bin/test.sh`
  полностью зелёный.
- Пуш в remote — не агентская операция.

## Цифры

48 задач проведено через доску за время разработки, ~4 300 строк кода плагина,
~5 100 строк тестов,
21 скрипт, 479 проверок в наборе (все зелёные).

## Идеи развития (v2)

- состояние в DSH-storage (`storageDomain`) и Typert-стрим для живых обновлений;
- инструмент `kanban_move` для агентов вместо файловых операций;
- полноширинная панель доски (слот `main`) вместо таба в сайдбаре.
