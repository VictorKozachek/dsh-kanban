# Скил: проверка совместимости инструментов и плагинов

Ревьювер не принимает задачу, пока не убедился, что изменения не ломают
**запрос к модели** и загрузку плагинов. Код может быть красивым, но сессия не
ответит — это провал.

## 1. Имена инструментов

Имя инструмента для провайдера должно соответствовать `^[A-Za-z0-9_-]+$`:
без точек, слэшей, пробелов и кириллицы.

Проверь изменённые плагины/регистрации:

```bash
# пример: все имена tools из request/header в логе сессии
node -e '...'   # или посмотри request/header в session.v4.jsonl.zstd
```

Плохой пример: `memory.search` → `Invalid 'tools[32].name'` (DeepSeek API).
Хороший: `memory_search`.

## 2. Source kind сообщений

DSH v4 запрещает `source.kind: "plugin"` — нужен producer-owned kind (как
`time-context` → `kind: "time-context"`, память → `kind: "dsh-memory"`).
Симптом: `format v4 message requires a producer-owned source kind`,
`This turn failed`. Проверь плагины, которые добавляют `user`-сообщения
(`createUserMessage`/свои конструкторы), и их тесты.

## 3. Smoke-запрос к модели

После включения плагина/изменения **сам** открой сессию (или попроси
исполнителя) и отправь короткий prompt. Убедись, что:
- ответ пришёл, ход завершился;
- в логе нет `assistant/attempt` с `INVALID_REQUEST`/`format v4`/`tools[`;
- сессия не осталась `running`/с непустой очередью inbox.

## 4. Тесты и логи

- Прогони `bin/test.sh` (или целевые тесты) — падение = немедленный возврат в
  `in-progress` с командой и выводом.
- Проверь `~/Library/Logs/DeepSeek Harness/` на новые crash-логи; `host stopped`
  без стека — это штатный выход, а не доказательство поломки.
- Если плагин внешний и проверить нельзя — верни задачу с конкретным
  воспроизведением и логом, а не «принято».

## Вердикт

Принято — только если имена tools валидны, source kind корректен, smoke-запрос
прошёл, тесты зелёные. Иначе — замечания в карточку и `in-progress`.
