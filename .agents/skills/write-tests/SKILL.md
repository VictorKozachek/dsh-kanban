# Скил: тесты как часть работы

Тесты — не опция, а часть результата. Ревьювер вернёт задачу без них, а
тестировщик не примет.

## Что покрывать

- **Unit** — каждое новое правило/функция/ветка: границы, пустые значения,
  ошибки, таймауты, повторные вызовы.
- **Интеграционный** — там, где код встречается с внешним миром:
  - вызовы API (свой сервис, клиент, SDK) — подмена на fake/fixture, проверка
    успешного ответа, ошибок, таймаута и ретрая;
  - БД/хранилище — реальная схема на временной базе или контрактный fake;
  - CLI/файловая система — временный каталог, коды возврата, права;
  - сеть — локальный сервер/мок, не реальный интернет.

## Как писать

- Тест проверяет **поведение из карточки**, а не реализацию: при регрессии он
  должен упасть.
- Один тест — одна причина падения; имя описывает сценарий.
- Фикстуры — в тесте/рядом с тестом, без общих мутабельных данных.
- Не оставляй «вечно зелёные» тесты (`assert.ok(true)`), тесты без assert и
  тесты, которые ходят в реальную сеть.

## Перед сдачей

1. Прогони тесты в своём worktree и запиши команду/результат в `note`:
   `bin/task-move.sh <id> in-review --note "тесты: <команда> — N passed"`.
2. Если тест невозможен (нет окружения/внешний сервис), явно напиши почему и
   что проверено вручную; это исключение, а не норма.
3. Не коммить сломанные тесты и не отключай их, чтобы «прошло».
