# Скил: сообщение коммита при слиянии задачи

Задачу вливает **только оркестратор**, и только через `bin/task-commit.sh`.
Ревьювер, тестировщик и исполнитель ветку не сливают: их дело — двигать карточку
до `ready`.

## Правило сообщения

```
[{SHORT_BRANCH_NAME}] Message
```

- `{SHORT_BRANCH_NAME}` — короткое имя ветки задачи: **ключ трекера**, если он
  есть в имени ветки, иначе последний сегмент имени.
- `Message` — одна строка: что именно сделано в задаче. Обычно название
  карточки; можно передать точнее через `--message`.
- Первая строка коммита — ровно этот формат, без префиксов `feat:`, `fix:` и
  без перевода строк.

| Полная ветка | Короткое имя | Сообщение |
|---|---|---|
| `release/NJ-001` | `NJ-001` | `[NJ-001] Починить экспорт QR` |
| `feature/NJ-42-fix-cache` | `NJ-42` | `[NJ-42] Починить инвалидацию кеша` |
| `task/007` | `007` | `[007] Описать протокол слияния` |

Ключом считается шаблон `[A-Z][A-Z0-9]*-<число>` (как ключ Jira).

## Как это делается

```bash
# из ОСНОВНОГО чекаута, после того как тестировщик перевёл карточку в ready
bin/task-commit.sh 007                                  # сообщение = название карточки
bin/task-commit.sh 007 --message "Починить экспорт QR"  # своя формулировка
bin/task-commit.sh 007 --branch release/NJ-001 --dry-run # посмотреть, что получится
```

Скрипт:

1. берёт карточку из рабочего дерева задачи (или из ветки), проверяет, что
   статус `ready`, и отказывается работать иначе;
2. выводит короткое имя из ветки и собирает сообщение;
3. делает `git merge --no-ff` в текущую ветку с этим сообщением;
4. переводит карточку в `merged` и коммитит её.

`--dry-run` показывает ветку, короткое имя, целевую ветку и итоговое сообщение,
ничего не меняя.

## Пуш — только человек

`git push` **не выполняет ни один агент и ни один скрипт набора**. Пуш делает
человек руками, когда все задачи готовы и закоммичены:

```bash
git push <remote> <ветка>
```

Причина простая: локальный коммит обратим (`git reset`), отправленный — уже нет.
Поэтому доска и протокол заканчиваются на `merged` = «закоммичено локально»;
факт пуша нигде не отмечается.

## Частые ошибки

- **Слить мимо скрипта.** `bin/task-move.sh <id> merged` протокол не разрешает:
  сообщение коммита останется без правила. Только `bin/task-commit.sh`.
- **Взять сообщение из ветки, а не из задачи.** Короткое имя — из ветки,
  `Message` — про суть задачи; `Merge branch 'task/007'` не подходит.
- **Пушить из сессии агента.** Даже «чтобы проверить». Пуш — шаг человека.
- **Сливать из рабочего дерева задачи.** `task-commit.sh` откажется: слияние
  делается в основном чекауте.
