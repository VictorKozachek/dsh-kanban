# Онбординг: от установки до первого наряда

Это пошаговый путь для нового пользователя: поставить плагин, подключить **свой**
проект, собрать команду из четырёх ролей и провести первую карточку по доске.
Шаги проверены на чистом профиле DSH и на отдельном тестовом проекте.

> Коротко: плагин — это доска и сторож. Протокол задач (`AGENTS.md`, `bin/task-*`,
> `.kanban/`) живёт в **вашем проекте**: агент читает его из рабочей директории.

![Как работает доска: карточка проходит от бэклога до слияния](dsh-kanban/docs/onboarding-demo.gif)

## Что понадобится

- DeepSeek Harness **0.2.1-rc.3+** (приложение или `dsh web`);
- `git` — задачи создаются в git-worktree;
- `node` — скрипты (`bin/node.sh` находит Node сам);
- `python3` — часть скриптов установки и тестов;
- проект — git-репозиторий хотя бы с одним коммитом.

## Шаг 1. Поставить плагин

```bash
git clone https://github.com/VictorKozachek/dsh-kanban.git
cd dsh-kanban

bin/install-kanban.sh desktop    # Electron-приложение
# или
bin/install-kanban.sh            # профиль web (dsh web)
```

Перезапустите DSH: профиль читает список бандлов при старте.

Проверка: откройте разговор, справа в полосе вкладок нажмите **+** и добавьте
**«Канбан»**. Пресеты ролей ставить отдельно не нужно — они регистрируются при
каждом старте плагина.

## Шаг 2. Подключить свой проект

Плагин по умолчанию смотрит на `$HOME/projects/dsh-kanban` — это пример. Свой
проект укажите в **профильном** патче `~/.dsh/cordis.patch.yml` (не в файле
репозитория: он под git и обновится вместе с плагином):

```yaml
- id: ui-kanban
  config:
    boards:
      - /Users/you/projects/my-project      # ваш проект
    roots: []                                # деревья для вложенных досок
    # ignore:                                # копии/эксперименты не обходить
    #   - /Users/you/projects/**/tmp
```

`boards` — проекты, чьи `.kanban/tasks` обслуживаются; `roots` — деревья, где
сторож сам находит доски компонентов. Учтите: override заменяет `config`
целиком, поэтому перечислите всё нужное.

Перезапустите DSH. Проверка:

```bash
cat /tmp/dsh-kanban-watch.diag.json
```

В `applied.boards` должен появиться ваш проект (или его компоненты), `fatal` —
`null`. Если проекта нет — проверьте путь и перезапуск.

## Шаг 3. Положить протокол в проект

Одна команда разворачивает в проекте всё, что нужно агентам и скриптам:

```bash
~/dsh-kanban/bin/kanban-init.sh ~/projects/my-project
```

Она копирует `bin/` (задачи, доска, doctor), `AGENTS.md`, формат карточек,
`.kanban/board.json`, `.gitignore`-блок и `dsh-kanban/lib/watcher-core.js`
(нужен `board-status`). Существующие файлы не перезаписываются; `--print`
показывает план, `--force` перезаписывает.

Проверка:

```bash
cd ~/projects/my-project
bin/doctor.sh                # что установлено и чего не хватает
bin/board-status.sh          # пустая доска — это нормально
git add -A && git commit -m "kanban: протокол задач"
```

> `bin/task-*` работают от корня проекта, поэтому запускайте их из проекта (а для
> задачи с worktree — из `worktrees/<id>`, там её карточка).

## Шаг 4. Собрать команду

1. В сайдбаре добавьте **workspace** — корень вашего проекта.
2. Создайте сессию **`dispatcher`** (оркестратор): New Session → пресет
   `dispatcher`.
3. В том же workspace создайте ещё три: **`worker`**, **`reviewer`**,
   **`verifier`**.
4. Откройте вкладку **«Канбан»** (правый сайдбар → **+** → «Канбан»).

Роли сторож подхватывает сам из выбора пресета и пишет карту в
`.kanban/.watcher-roles.json`. Для **нескольких исполнителей** перечислите их
сессии в `.kanban/.workers.json` (порядок = приоритет выдачи):

```json
["session-…", "session-…"]
```

## Шаг 5. Первая карточка

Из корня проекта:

```bash
bin/task-new.sh "Починить экспорт QR"
```

Скрипт создаст `worktrees/001`, ветку `task/001` и карточку в этой ветке; доска
сразу покажет её в `todo`.

Выдача исполнителю — один из способов:

- перетащить карточку `backlog → todo` в GUI (асайн выберет свободного);
- или вручную:

```bash
bin/task-move.sh 001 todo --owner <session-id-исполнителя>
```

После этого сторож отправит исполнителю наряд «бери в работу». Дальше цикл:

| Шаг | Кто | Команда |
|---|---|---|
| Взял в работу | исполнитель | `bin/task-move.sh 001 in-progress --owner "$DSH_SESSION_ID" --role worker` |
| Готово, на ревью | исполнитель | `bin/task-move.sh 001 in-review --note "что сделано; как проверять"` |
| Принято | ревьювер | `bin/task-move.sh 001 testing` |
| Проверено | тестировщик | `bin/task-move.sh 001 ready` |
| Слияние | оркестратор | `bin/task-commit.sh 001` (из основного чекаута) |

Все переходы и правила — в `AGENTS.md` и `.kanban/tasks/README.md`.

## Шаг 6. Проверить, что сторож работает

- `/tmp/dsh-kanban-watch.diag.json` (`DSH_KANBAN_DIAG_PATH` — переопределить):
  - `applies[]` — конфиг, число досок/наблюдателей, ошибка;
  - `events[]` — `announce`, `deliver-once`, `delivered`, причины отказов;
  - `heartbeatAt` — плагин жив (раз в 20 с).
- `.kanban/.watcher-pending.json` — недоставленные наряды; при старте чистится от
  мёртвых сессий и невалидных owner-ов.
- `bin/board-status.sh` — что видит доска.

## Частые проблемы

| Симптом | Причина и что делать |
|---|---|
| Нет вкладки «Канбан» | плагин не установлен/не перезапущен: `bin/install-kanban.sh desktop`, перезапуск |
| Доска пуста | нет `.kanban/tasks` в рабочей директории сессии или карточки не `*.md` |
| Наряд не пришёл | сессия роли не выбрана пресетом (карта `.watcher-roles.json` пуста); `owner` не session-id; доска не в `boards`/`roots` |
| Сессия стала `standard` | пресеты не зарегистрировались: обновите плагин и перезапустите; id пресета в логе сессии сохранён |
| Роль — subagent-сессия | prompt ей невозможен: пересоздайте роль обычной корневой сессией с пресетом |
| `git worktree add` не удался | проект не git-репозиторий или нет коммита |
| `bin/node.sh` пишет «нужен node» | задайте `DSH_NODE=/путь/к/node` |
| `bin/board-status.sh` падает на импорте | скопируйте `dsh-kanban/lib/watcher-core.js` (шаг 3) |
| Дублей карточек/шум в диагностике | клоны в `tmp/` попали в обход: добавьте `ignore` в профиль (шаг 2) |

## Что дальше

- **Бэклог и спецификации**: `bin/spec-new.sh "Название"` →
  `bin/task-new.sh "..." --backlog --spec NNN`; выдача — `bin/backlog-fill.sh`
  при недоборе `todo` (порог `minTodo` в `.kanban/board.json`).
- **Несколько исполнителей**: `.kanban/.workers.json` (порядок = приоритет).
- **Слияние**: только `bin/task-commit.sh` из основного чекаута; пуш делает
  человек.
- **Диагностика и нюансы**: `KANBAN.md`, раздел «Диагностика сторожа».

## Ограничения текущей версии

- Протокол (`bin/`, `AGENTS.md`, `.kanban/`) копируется в проект вручную; после
  обновления плагина скопируйте скрипты заново. Автоматический
  `bin/kanban-init` — в планах.
- `bin/board-status.sh` требует `dsh-kanban/lib/watcher-core.js` из шага 3.
- Пресеты ролей меняются только у новой сессии: у существующей сессии пресет
  зафиксирован в её логе.
