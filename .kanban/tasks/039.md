## Задача

Механика выдачи из `backlog` и хранение спецификаций. Основание — спека
`.kanban/specs/001-backlog.md` (разделы «Минимум todo и выдача»,
«Спецификации»). Зависит от #038: статус `backlog` и переходы должны уже быть.

Что сделать:

1. **Конфиг минимума.** `.kanban/board.json` (tracked, новый файл):
   `{ "minTodo": 2 }`. Скрипты читают его; нет файла — значение по умолчанию
   (`minTodo: 1`); битый JSON — внятная ошибка и код 1, а не молчаливый дефолт.
2. **Пул исполнителей.** `.kanban/.workers.json` (gitignored): упорядоченный
   массив id сессий. Нет файла — fallback на единственного `worker` из
   `.kanban/.watcher-roles.json`. «Свободен» = в `.kanban/tasks/*.md` нет
   карточки со `status: in-progress` и `owner` этого исполнителя.
3. **`bin/backlog-fill.sh`** — запускает оркестратор (полуавтомат, так решено):
   - считает карточки в `todo`; если их `>= minTodo` — ничего не делает, код 0;
   - иначе берёт карточки `status: backlog` по возрастанию `id` (FIFO);
   - каждой находит первого свободного исполнителя (по порядку `.workers.json`);
     свободных нет — останавливается, печатает, сколько выдал и почему встал;
   - двигает карточку и закрепляет владельца переходом `backlog → todo --owner
     <id>` через `bin/task-move.sh` — правила протокола остаются в одном месте;
   - `--dry-run` — показать план, ничего не менять; `--min N` — переопределить
     минимум; коды возврата: 0 — ок (включая «нечего делать»), 1 — ошибка
     конфига/доски, 3 — backlog пуст при недоборе.
4. **Спецификации.** `bin/spec-new.sh "Название"` — заводит
   `.kanban/specs/<NNN>.md` по шаблону (следующий свободный номер, статус,
   `## Зачем`, `## Требования`, `## Вне скоупа`). Поле `spec` в карточках:
   добавить в `FIELDS` парсера (`watcher-core.js`) и `--spec <NNN>` в
   `bin/task-new.sh`; в клиентской половине показывать спеку в карточке/панели
   деталей, если поле есть.
5. **`.gitignore`** (в репозитории его нет — создать):
   `.kanban/.watcher-state.json`, `.kanban/.watcher-roles.json`,
   `.kanban/.watcher-pending.json`, `.kanban/.workers.json`, `worktrees/`,
   `.kanban/worktrees.json` — сверься с AGENTS.md и KANBAN.md, что закрыты
   именно служебные файлы.
6. Тесты: тесты скриптов в `bin/test-scripts.sh` или отдельный mjs-тест для
   разбора конфига и выбора исполнителя (на усмотрение исполнителя, без внешних
   зависимостей). Обязательные случаи: `todo` на минимуме → no-op; недобор →
   выдача до минимума по FIFO; свободных нет → 0 выдач; битый конфиг → код 1;
   fallback на `.watcher-roles.json`.
7. `KANBAN.md`: конфиг минимума, пул исполнителей, `backlog-fill.sh`,
   `spec-new.sh`, поле `spec`, `.gitignore`.

Не трогать: `AGENTS.md` (правит оркестратор), `package.json`.
