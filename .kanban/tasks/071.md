## Задача (M0)

Скелет Rust-хаба без интеграции с плагином: сервис, схема, auth, API, тесты.

### Состав

- `hub/` — cargo-проект (Rust): axum + tokio; SQLite (rusqlite или sqlx) в
  файле-томе; serde.
- Схема: `projects`, `instances` (id, project, last_seen, lease_until),
  `cards` (id, project, home_instance, rev, payload JSON, updated_at),
  `ops` (опционально журнал: op_id, card, rev, payload, at).
- API MVP:
  - `GET /healthz` — без auth;
  - `POST /v1/projects/:project/instances/:instance/heartbeat` — продление lease;
  - `POST /v1/projects/:project/cards/:id` — upsert снимка с `baseRev` (CAS;
    при устаревшей версии `409` и актуальная карточка в ответе);
  - `GET /v1/projects/:project/cards?after=<rev|timestamp>` — pull изменений;
  - `POST /v1/projects/:project/cards/:id/adopt` — смена `home_instance` после
    истечения lease (или явно диспетчером), увеличивает `rev`.
- Auth: `Authorization: Bearer <project-token>`; токен из конфига/ENV
  (`KANBAN_HUB_TOKENS=project:token,...`). Без токена — только healthz.
- Конфиг: `KANBAN_HUB_DB`, `KANBAN_HUB_ADDR` (по умолчанию `127.0.0.1:8787`),
  `RUST_LOG`.
- Dockerfile + `docker-compose.yml` (hub + volume), без Postgres.
- Тесты: `cargo test` на временной SQLite; happy path (создать/прочитать),
  CAS-конфликт → 409, adopt, heartbeat/lease.

### Критерии

- [ ] `cargo test` зелёный; `cargo run` поднимает сервис.
- [ ] curl-сценарий: создать карточку, получить по after, обновить с верной и
      неверной baseRev (409), adopt.
- [ ] `docker compose up` поднимает хаб (если Docker есть).
- [ ] README хаба: запуск, ENV, примеры API.

Файлы: `hub/`, `docker-compose.yml`. Не трогать: `dsh-kanban/lib/*` (это M1).
