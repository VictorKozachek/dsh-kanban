## Задача (issue #4, протокол)

Два писателя в одном worktree: вторая сессия правила те же файлы, «file changed
since it was read». `task-move` проверял owner только при взятии, параллельная
работа не обнаруживалась.

## Готово

- `bin/task-move.sh` при переходе в `in-progress` берёт замок
  `.kanban/.locks/<id>.json` (`sessionId`, `worktree`, `since`, `heartbeat`).
- Второй писатель получает отказ «карточку держит <session>»; обход — `--force`.
- Уход из `in-progress` снимает замок.
- Просроченный замок (`KANBAN_LOCK_TTL_MINUTES`, по умолчанию 12 ч) или замок
  мёртвой сессии перехватывается с предупреждением.
- В выводе «замок задачи <id>: <session> (worktree …)».
- `.kanban/.locks/` в `.gitignore` и шаблоне `kanban-init`.
- `bin/test-locks.sh` (7 проверок): взятие, отказ второму, `--force`, снятие,
  мёртвый замок. Полный набор: 531 проверка, зелёный.

## Ограничения

- Замок локальный для worktree/доски: он не заменяет `owner` и не мешает
  читать карточку.
- Heartbeat обновляется только вызовами `task-move`; при очень долгой работе без
  переходов TTL может истечь — тогда замок перехватывается с предупреждением.
