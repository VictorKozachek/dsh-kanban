## Задача

#043 научила `backlog-fill.sh` видеть занятость исполнителей в `worktrees/*`, но
**кандидатов на выдачу** он по-прежнему берёт только из `.kanban/tasks`
основного чекаута. Пока задачи нарезаются `--no-worktree`, это не всплывает; при
штатном режиме с рабочими деревьями карточка-кандидат живёт в ветке задачи, и
выдача из backlog не работает вообще. Тестировщик #043 воспроизвёл три случая
(наблюдения 1–3) — они и есть содержание задачи.

Что сделать в `bin/backlog-fill.sh`:

1. **Кандидаты — по слитому снимку доски**, той же семантикой, что у сторожа
   (`dsh-kanban/lib/index.js`): обходить основной `.kanban/tasks` и
   `worktrees/*/.kanban/tasks`, `.worktrees/*/.kanban/tasks`; копии одной
   карточки сливать по свежести `updated` (равенство — в пользу дерева); из
   дерева брать только одноимённую карточку `<id>.md`; отбрасывать файл, у
   которого id из front matter не совпадает с именем (проверка `liveId` как у
   сторожа). Сейчас снимок ключуется только по id, поэтому порченый
   `worktrees/077/077.md` с чужим id подменяет чужую карточку.
2. **Выдавать из слитого снимка**, а не из копии в основном чекауте: если main
   хранит устаревшую копию `backlog`, а в дереве та же карточка уже
   `in-progress`, задача не должна уехать второму исполнителю — слитый снимок
   даёт `in-progress`, и карточка пропускается. Обратный случай (свежий
   `backlog` только в дереве) — карточка должна выдаваться.
3. Не ломать уже сделанное: занятость из #043, FIFO по id, `--dry-run`,
   коды возврата, «backlog исчерпан: выдано N из M», строгий пул
   `.workers.json` с fallback на `.watcher-roles.json`.

Файлы задачи: `bin/backlog-fill.sh`, `bin/test-scripts.sh` (блок проверок
`backlog-fill`). Не трогать: `dsh-kanban/` (код плагина — эталон слияния берём
оттуда чтением), `AGENTS.md`, `KANBAN.md`, чужие карточки.

      `~/projects/awg` (вне песочницы).

      `worktrees/010/.kanban/tasks/010.md` — при недоборе она выдаётся
      свободному исполнителю (ветка задачи, карточка уезжает в его todo).
- [ ] main хранит устаревшую копию `010 backlog`, в `worktrees/010` копия
      `010 in-progress` у w1 — задача никому не выдаётся (слитый снимок видит
      `in-progress`), w1 считается занятым.
- [ ] Порченый файл `worktrees/077/077.md` с чужим id (`001`) не подменяет
      карточку `001`: занятость и выдача по `001` не меняются.
- [ ] Свежая копия в дереве побеждает main (status `backlog` в дереве, `in-progress`
      в main — выдаётся), равенство `updated` — в пользу дерева.
- [ ] `--dry-run` не меняет файлы; битые/пустые каталоги деревьев не ломают обход;
      сценарии #043 (занятость в worktrees, частичный backlog, пустой backlog,
      полный todo, пул исполнителей) остаются зелёными.
