## Задача (issue #7, на 19.11)

Команда **`/checkout`** — завершение рабочего дня. Каскад по иерархии:
все завершают/фиксируют работу, коммитят и **пушат**, синхронизируют карточки
с трекером, отчитываются наверх.

Связанный issue: https://github.com/VictorKozachek/dsh-kanban/issues/7

План MVP:
1. Персона manager: `/checkout` → наряд оркестраторам ниже; протокол
   «заверши/зафиксируй незавершённое, git status, commit, push, синк статусов».
2. Агрегатор `.kanban/.checkout/<YYYY-MM-DD>.md`: сделано/не доделано/на завтра/
   блокеры; неответившие за graceMinutes — отдельно.
3. Планировщик (позже): время/дни недели в конфиге, автозапуск, идемпотентность.
4. Отчёт пользователю через manager-сессию.

Открытые вопросы (решить до реализации):
- **push**: текущий протокол запрещает агентам `git push` («пуш — человек»),
  а checkout требует пушить. Варианты: manager просит подтверждение человека;
  отдельный режим для checkout; или разрешить push только manager/checkout.
- **ютрек**: уточнить, что имеется в виду (YouTrack? внешний трекер); нужен API,
  токен, маппинг статусов. Пока — зафиксировать как интеграцию.
- commits: «максимально закоммичено» — какие незавершённые изменения допустимы
  (WIP-коммит в ветку задачи?) и как не ломать main.

Критерии: отчёт дня с незапушенными ветками/незакоммиченными изменениями/
расхождениями статусов; повторный checkout не дублирует наряды.
