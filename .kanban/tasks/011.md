## Задача
Guard выдачи срабатывает на **любой** переход в `in-progress`, а не только из
`todo`. Из-за этого документированные возвраты чужой ролью отклоняются без
`--force`: ревьювер `in-review` → `in-progress`, тестировщик `testing` →
`in-progress`, оркестратор `ready` → `in-progress` и `blocked` → `in-progress`.
Ревью #006 проверил все четыре — везде отказ «закреплена за <owner>».

Нужно решение: сузить guard до перехода из `todo` (и пустого статуса) **или**
разрешать смену владельца по роли, когда карточку возвращают в работу. После
решения — привести документацию в соответствие с кодом.

## Критерии готовности
- [ ] выбран вариант (сузить guard / разрешать возврат по роли) и записан в
      `AGENTS.md` явно, а не намёком
- [ ] все четыре возврата работают по протоколу без `--force`, на каждый — тест
- [ ] попытка забрать чужую карточку из `todo` по-прежнему отвергается
- [ ] `bin/test.sh` зелёный; правки сделаны в `awg` и перенесены в `m-future`

## Заметки
Источник — ревью #006 (ревьювер `reviewer-006`), пункт 6. Предсуществующее:
guard введён коммитом `ff729de`; новые строки документации говорят только про
`todo` → `in-progress`, то есть доки уже кода.

Смежное: карточки возвращают в работу с причиной в `note` — это ещё и место, где
`since` должен обновляться, а `role` меняться на того, кто вернул.
