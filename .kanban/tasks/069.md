## Задача

Проверить путь **нового пользователя**: он ставит плагин с нуля и должен сам,
без подсказок, понять что это, зачем и как с ним работать.

Контекст: завтра пользователь принесёт концепт идеи онбординга — сначала
обсуждаем концепт, эту карточку уточняем по итогам, потом исполняем.

### Что проверить (сценарий «как будто впервые»)

1. **Установка**: `git clone` → `bin/install-kanban.sh` (web/desktop) → рестарт.
   Понятно ли, что пресеты уже внутри плагина? Куда смотреть, если после
   рестарта нет вкладки «Канбан»? Что делать с `cordis.patch.yml`
   (boards/roots — чужие пути `$HOME/projects/...`)?
2. **Первые шаги**: добавить воркспейс → создать 4 сессии с пресетами
   (`dispatcher`/`worker`/`reviewer`/`verifier`) → открыть вкладку доски.
   Хватает ли README, или человек теряется: пресеты, карта ролей, асайн,
   работу в worktree, «почему доска пустая»?
3. **Типичные грабли новичка**:
   - проект без `git` (worktree не создать);
   - `bin/board-status.sh` и `bin/test.sh` без `node`/`python3`;
   - карточки/задачи в`.kanban` не появляются, потому что нет `task-new`;
   - сторож не раздаёт наряды: роли не заполнены, сессия не та, owner не session-id;
   - путь к проекту не совпадает с `boards` (доска не видит доски).
4. **Документация и UX подсказки**: README (EN/RU), KANBAN.md, `--help` скриптов,
   сообщения ошибок (`task-new`/`task-move`/`task-assign`) — понятны ли они без
   чтения исходников; нужен ли «Быстрый старт на 5 минут»/скринкаст-текст.
5. **Чистый профиль**: прогнать установку в изолированном `DSH_HOME`/профиле,
   убедиться, что ничего не осталось от машины разработчика; проверить в
   харнессе, что плагин стартует на «чистом» профиле.

## Найденные ступоры (по приоритету)

1. **Нет инициализации проекта пользователя.** Все скрипты считают `ROOT`
   каталогом репозитория плагина (`BASH_SOURCE/..`), а не проектом пользователя:
   `bin/task-new.sh` создаст карточки в клоне плагина, а не в вашем репозитории.
   Новичку не очевидно, как «подключить доску к своему проекту». Варианты:
   `bin/kanban-init <путь>` (копирует `bin/`, `.kanban/`, `AGENTS.md`) или
   поддержка `KANBAN_ROOT`/`--root` во всех скриптах.
2. **Дефолты `boards`/`roots` — пути разработчика** (`$HOME/projects/dsh-kanban`,
   `.../ai-fabric/aif-project`). Новичок со своим путём не увидит доску. README
   теперь подсказывает профильный override; стоит добавить в `install-kanban.sh`
   `--boards/--roots` или печатать «куда положить свой проект» после установки.
3. **Требования неполные:** README говорит «node + git», но `install-kanban.sh`,
   `install-presets.sh`, `test.sh`, `task-usage.sh` используют `python3`. Добавить
   python3 в Requirements и проверку в установщике.
4. **Вкладка «Канбан»**: в README «нажмите + в полосе вкладок справа». Нужен
   реальный скриншот этого места (у пользователя на скриншоте видны вкладки
   «Файлы | Канбан»); макета недостаточно.
5. **Первый цикл не показан**: нет демо-карточки/шагов «создал карточку → увидел
   наряд в сессии → перевёл в in-review». Для новичка это главный «ага-момент».
6. **Git-требование**: без git-worktree карточка создаётся в текущей директории
   (предупреждение), но не сказано, что для полноценного цикла нужен git-репозиторий
   и хотя бы один коммит.
7. **Роли после рестарта**: если сессии созданы до установки плагина (или пресеты
   потеряны), карта `.watcher-roles.json` пуста — наряды не уходят. Нужен
   диагностический шаг «проверь карту ролей» (сейчас есть только warning в diag).
8. **Диагностика спрятана**: `/tmp/dsh-kanban-watch.diag.json` — путь для
   разработчика; новичку нужен `bin/doctor`, который проверит: конфиг, число
   досок, карту ролей, pending, свежесть heartbeat, и скажет, что не так.
9. **Клоны `tmp/`**: без `ignore` сторож видит 71 доску вместо ~43 и сыпет
   `deliver-skipped-board`. В README добавлен `ignore`, но в установщике его нет —
   для новичка это шум в диагностике.

## Предлагаемый минимум под концепт

- `bin/doctor` (проверка установки и первых шагов, печатает «что сделать»);
- `bin/kanban-init <project>` (или `KANBAN_ROOT`) — подключить доску к своему проекту;
- `install-kanban.sh --boards <путь>` + печать подсказки;
- в README: python3 в требованиях, реальный скриншот вкладки «Канбан»,
  демо-цикл «первая карточка → наряд».
