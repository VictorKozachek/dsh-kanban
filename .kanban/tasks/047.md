## Задача

Дать клиентской половине плагина возможность **выполнить перемещение карточки на
хосте** (асайн/возврат). Сейчас клиент умеет только читать: в
`dsh-api-workspace-files` есть `list/read/readBytes/stat/changes`, записи нет.
Основание: `.kanban/specs/002.md` («Архитектура»).

### Спайк (обязательная часть)

Разобраться, каким каналом клиент→хост можно вызвать действие, и зафиксировать
выбор в заметке карточки с обоснованием. Порядок приоритета:

1. **свой host-remote** по образцу `remote.workspaceFiles`: изучить
   `@deepseek-ai/dsh-api-workspace-files` внутри бандла приложения (host-часть
   регистрирует сервис через `Remote`/`TypertRemoteService` из
   `@deepseek-ai/dsh-typert-protocol`, клиенту приходит как `remote.<имя>`);
   проверить, резолвится ли пакет протокола из нашего плагина (мы грузимся из
   симлинка `dsh-kanban/`, peer-зависимость `@deepseek-ai/cordis` уже работает) и
   хватает ли документированного API, чтобы объявить remote без генератора
   `dsh-typert-generator`;
2. **переиспользовать существующий remote**: например, терминальный контроллер
   или session-controller — выполнить `bin/task-assign.sh <id>` в workspace
   сессии (учти политику approvals: вызов может требовать подтверждения; для
   действия человека в GUI это допустимо, но опиши, как это выглядит);
3. **деградация**: промпт оркестратору через `sessionController.prompt`
   (сессия диспетчера из `.kanban/.watcher-roles.json`) с просьбой асайнить
   карточку; оркестратор выполняет `bin/task-assign.sh`. Медленно, но без нового
   протокола; допустима как fallback, если 1 и 2 не взлетели.

### Host API (форма не зависит от канала)

- `assign({ sessionId, cardId })` → `{ ok, status, owner?, message }`;
  `unassign({ sessionId, cardId })` → то же;
- сессия → корень проекта: сопоставить `sessionId` с workspace (через
  `ctx.sessionController`/`dsh-api-workspace-controller`) и доской из `boards`;
  карточку искать по слитому снимку доски (как сторож);
- выполнять **только** `bin/task-assign.sh` из корня проекта, аргументы массивом
  (никакого шелла из строк клиента), `cardId` валидировать `/^[0-9]{3,}$/`;
- любые действия, кроме `backlog ↔ todo`, через этот канал запрещены; ошибки
  возвращать текстом, не падать.
