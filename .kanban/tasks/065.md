## Задача

Тестировщик #062 заметил: дефолтный путь `bin/gen-role-presets.sh` (без
`--standard`) падает на macOS из-за `mktemp` с суффиксом:

```bash
# bin/gen-role-presets.sh:75
TEMP_STANDARD="$(mktemp "${TMPDIR:-/tmp}/standard.patch.XXXXXX.yml")"
```

BSD `mktemp` (macOS) требует, чтобы шаблон **заканчивался** на `XXXXXX`; суффикс
`.yml` даёт `mkstemp failed: Invalid argument`. GNU `mktemp` суффикс разрешает —
поэтому на Linux/в тестах дефект может не проявляться, а у пользователя на
машине сломается первая же генерация без `--standard`.

### Что сделать

1. Починить: `TEMP_STANDARD="$(mktemp "${TMPDIR:-/tmp}/standard.patch.XXXXXX")"`
   (без суффикса), при необходимости переименовать/дописать `.yml`; либо
   `mktemp …/standard.patch.XXXXXX` + `mv` в отдельный файл с расширением.
2. Убрать зависимость от GNU-расширений в других `mktemp` этого скрипта (если есть).
3. Регрессия в `bin/test-scripts.sh`: запуск `bin/gen-role-presets.sh` **без**
   `--standard` на окружении, где шаблон находится штатно (или с поддельным
   `TMPDIR`/`mktemp`-шимом, эмулирующим BSD-поведение) — скрипт не падает;
   отдельная проверка, что суффикс не передаётся в `mktemp`.
4. `bin/test.sh` зелёный; чистом клоне — тоже.

Файлы задачи: `bin/gen-role-presets.sh`, `bin/test-scripts.sh`.
Не трогать: `presets/role-presets.*`, `dsh-kanban/lib/*`, `.kanban/` (кроме карточки).
