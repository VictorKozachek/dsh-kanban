## Задача

После апдейта DSH с `0.1.7-rc.1.20260924.1` на **`0.2.1-rc.3`** (28.10, апдейт
установился штатно — graceful shutdown подтверждён живьём) диагностический
харнесс `bin/host-shutdown-check.mjs` перестал запускаться: все четыре
сценария, **включая control**, падают одинаково — Host завершается до `ready`,
код 1, ~85 мс. Значит сломан не плагин, а контракт запуска Host'а/сборки
временного профиля, на который харнесс опирался.

Известное на момент постановки (проверить, не догадываться):

- В бандле новой версии появился второй вход:
  `dsh/node_modules/@deepseek-ai/dsh-desktop-host/lib/cli.js` рядом с
  `lib/index.js`; в старой версии был только `index.js`. Возможно, Host теперь
  запускается иначе (через cli.js, другие аргументы/переменные).
- Появился `Resources/runtime/` с `bin/`, `cli/`, `office-skills/`,
  `primary-runtime/`, `versions.json` (node 24.21.0, pnpm 11.28.5) — раскладка
  рантайма изменилась относительно зашитых в харнессе путей
  (`RUNTIME_DIR = app.asar/dsh`, `HOST_ENTRY = .../dsh-desktop-host/lib/index.js`).
- Харнесс подменяет в тексте энтри литерал `"--port", "19387"` на `"0"`.
  Надо сверить с `app.asar → lib/main.js` новой версии, как оболочка реально
  спавнит Host и какие аргументы передаёт, и не завязываться на литерал.
- Вероятно, профиль, собираемый харнессом «с нуля», не учитывает новые поля
  `0.2.x`; причина фатального выхода должна быть видна в **stderr Host'а** —
  харнесс должен его показывать при падении до `ready` (сейчас видно только код).

Что сделать:

1. Починить `bin/host-shutdown-check.mjs`: определять вход/аргументы Host'а и
   раскладку рантайма по фактическому бандлу версии (по `lib/main.js` и
   `package.json` бандла), а не жёстко; при падении до `ready` печатать
   stdout/stderr Host'а и причину; `skip` оставить для случая «бандла нет».
2. Прогнать на 0.2.1-rc.3: control / board / roots / events — все четыре с
   бюджетами ack ≤ 5 с, exit ≤ 10 с, код выхода 0; с плагином — зелёные
   (graceful shutdown после #053). Если на новой версии плагин снова не даёт
   выйти — это отдельный сигнал, зафиксировать в карточке и вернуть
   оркестратору.
3. Заодно проверить, что на 0.2.1 живо то, что завязано на внутренности
   приложения: канал `kanbanCardActions` (живой дроп из GUI) и доставка
   нарядов сторожем — но только как наблюдения; если что-то сломано из-за
   апгрейда — отдельная задача, не расширять эту.

Файлы задачи: `bin/host-shutdown-check.mjs` (и, если нужно, маленький
вспомогательный файл рядом). Не трогать: `dsh-kanban/lib/*`, `AGENTS.md`,
`KANBAN.md`, `.kanban/` (кроме своей карточки).
