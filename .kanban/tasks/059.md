## Задача

Реализовать **чтение** обзора дочерних досок: host-служба `kanbanChildren` +
вторая вкладка «Дочерние доски» в правом сайдбаре. Полное описание — спека
`.kanban/specs/004.md`, пункты 2, 4, 5, 6, 7.

Пользователь-родитель (сессия в своём workspace) видит сводку по доскам дерева
из `.kanban/children.json` этой сессии и может открыть доску ребёнка только для
чтения.

### Что сделать

1. **Host-служба `kanbanChildren`** в `dsh-kanban/lib/index.js` — по образцу
   `kanbanCardActions` (`registerCardActionsService`): typertRemote-служба,
   `GET`-подобная операция `read`/`overview` с аргументом
   `{ request: { sessionId } }`. Логика — чистая функция в новом
   `dsh-kanban/lib/children.js`: прочитать `<cwd>/.kanban/children.json`
   (cwd сессии — через тот же механизм, что у сторожа для ролей), разобрать
   `boards[].path` (относительные — от cwd, абсолютные — как есть), для каждой
   доски собрать снимок: `<board>/.kanban/tasks/*.md` + одноимённые карточки из
   `<board>/worktrees/*/.kanban/tasks/<id>.md` и `<board>/.worktrees/*/...`,
   слияние по свежести `updated` (равенство — дерево). Переиспользовать чистое
   из `dsh-kanban/lib/watcher-core.js` (разбор карточки, слияние) — не
   копировать.
2. Ответ: `{ ok: true, value: { boards: [{ path, title, cards, problems }], problems } }`;
   ошибка одной доски (нет каталога, битый манифест, недоступно) не валит
   остальные; битый/отсутствующий манифест — понятный `ok:false` или пустой
   список с подсказкой (решите и зафиксируйте тестом). **Никаких операций
   записи** — служба только читает.
3. **Клиент** `dsh-kanban/lib/client.js`: зарегистрировать второй таб
   (`ctx.sidebarRightTabs.register` со своим id, `kind: "extension"`,
   заголовок/гид), свои `slots` body/title, словари ru/en. Вкладка:
   - список досок деревом по путям (отступ по числу сегментов), название
     (title или последний сегмент), счётчики по статусам, карточки `in-progress`
     с id/названием/владельцем/ролью/updated, ошибки чтения доски;
   - клик по доске — read-only колонки её карточек, клик по карточке — панель
     деталей без действий;
   - опрос раз в 3 с, кнопка ⟳, пустые состояния (нет манифеста → подсказка
     `bin/board-children.sh --root …`; досок нет; ошибка Remote — баннер);
   - **read-only:** никакого drag&drop, кнопок перевода и тоста «переношу…».
4. **Тесты:**
   - `dsh-kanban/test/children.test.mjs` — host-логика на временном дереве
     (манифест, слияние с worktree, доска только в ветке, битая доска,
     две доски, счётчики);
   - рендер вкладки — новый тест (по образцу `render.test.mjs`, поддельный
     cordis-контекст): список, дерево, счётчики, drill-down, пустые состояния и
     **отсутствие обработчиков переноса/кнопок**;
   - при желании расширить `dsh-kanban/test/render.test.mjs`, но свои проверки
     держать в отдельном файле, чтобы не раздувать существующий.

Файлы задачи: `dsh-kanban/lib/children.js` (новый), `dsh-kanban/lib/index.js`,
`dsh-kanban/lib/client.js`, `dsh-kanban/test/children.test.mjs` (новый),
`dsh-kanban/test/children-render.test.mjs` (новый). Не трогать: `bin/*`
(скрипт — #060), `KANBAN.md`, `AGENTS.md`, `FEATURES*.md`, `.kanban/` (кроме
своей карточки), host-правила сторожа (`boards`/`roots`, доставка нарядов).

Исключение по `KANBAN.md`: разрешено добавить **только строки новых файлов** в
таблицу «Что лежит в проекте» (проверка «таблица файлов не отстаёт от
набора» иначе покраснеет — так же делали в #058). Разделы и текст не
тактика — их пишет #061 после слияния.
