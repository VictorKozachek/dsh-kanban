## Задача

После слияния #041 сторож видит карточки в рабочих деревьях, и задачи снова можно
вести в `worktrees/<id>`. А `bin/backlog-fill.sh` (#039) определяет занятость
исполнителя только по `.kanban/tasks` основного чекаута — исполнитель, у которого
карточка в `in-progress` внутри `worktrees/<id>/.kanban/tasks`, считается
свободным и получает вторую задачу. Тестировщик #039 воспроизвёл это на стенде.

Что сделать:

1. `bin/backlog-fill.sh`: считать занятость по всем доскам проекта — основной
   чекаут `.kanban/tasks/*.md` **и** рабочие деревья
   `worktrees/*/.kanban/tasks/*.md`, `.worktrees/*/.kanban/tasks/*.md`. Из
   дерева брать только одноимённую карточку `<id>.md` (та же семантика, что у
   сторожа в `dsh-kanban/lib/index.js`, чтобы не приписывать унаследованные копии
   чужих карточек). Правило «занят = есть карточка в `in-progress` с этим
   `owner`» не меняется, меняется только источник данных.
2. Заодно поправить сообщение о частичном `backlog`: сейчас строка «остановка:
   backlog пуст» появляется, только когда очередь пуста полностью; при недоборе
   `2` и одной карточке выдаётся одна, а внятной строки «backlog исчерпан,
   выдано 1 из 2» нет. Добавить честный итог: сколько выдали и сколько недобрали
   из-за исчерпания backlog.
3. Тесты (там же, где живут проверки `backlog-fill`: `bin/test-scripts.sh`):
   - исполнитель с `in-progress` в `worktrees/077/.kanban/tasks` не получает
     задачу, следующий свободный получает;
   - унаследованная копия чужой карточки в дереве занятости не создаёт (если
     реализация берёт только одноимённую);
   - битый/пустой каталог дерева не ломает подсчёт;
   - сценарий частичного backlog: код 3 и строка «выдано N из M, backlog
     исчерпан».

Файлы задачи: `bin/backlog-fill.sh`, `bin/test-scripts.sh` (блок проверок
`backlog-fill`). Не трогать: `dsh-kanban/` (код плагина), `AGENTS.md`, чужие
карточки.

## Критерии готовности

- [ ] `bin/test.sh` зелёный, включая новые проверки `backlog-fill`, кроме
      известной сверки с `~/projects/awg` (вне песочницы).
- [ ] Временная доска: `todo` недобирает, первый исполнитель держит
      `in-progress` в `worktrees/077/.kanban/tasks` — задача уходит следующему
      свободному, первому не уходит.
- [ ] Унаследованная копия чужой карточки в дереве не считается занятостью
      этого исполнителя.
- [ ] Частичный backlog: недобор 2 при одной карточке → выдана одна, код 3,
      в выводе есть «выдано 1 из 2» и «backlog исчерпан».
- [ ] `--dry-run` по-прежнему ничего не меняет; поведение при пустом backlog и
      при полном `todo` не изменилось.
