## Принятые решения (11.11)

1. Центральный хаб — да; локальные копии остаются для скорости/офлайна.
2. Хостинга пока нет: MVP запускается локально (cargo run / docker compose),
   позже переносится в Docker. Postgres не обязателен на старте (SQLite в томе).
3. Файлы `.kanban/tasks/*.md` остаются локальной правдой; хаб — координация/бэкап.
4. Роли строго локальные: карточка и все её роли живут на одном инстансе; чужие
   карточки видны read-only, наряд на другую машину не уходит.

Следствие: **одна карточка — один домашний инстанс** (`homeInstance`), версия
`rev` + CAS на хабе, lease/heartbeat, adopt осиротевших карточек. Конфликтов
статусов нет, кроме гонки adopt — она решается `rev`/lease (409 + перечитывание).

Никакого git-транспорта: хаб — Rust-сервис с HTTP/WS и SQLite.

Карточки этапов: #071 (M0 хаб), #072 (M1 синк), #073 (M2 read-only/adopt).

## Уточнение (18.11)

Для команды из 4 человек модель уточнена: не `homeInstance`, а **lease/claim**
(карточку пишет один держатель lease, любой участник может взять после release/TTL).
См. `docs/distributed-kanban.md`.
