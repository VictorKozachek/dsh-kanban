## Задача
После #031 сторож сам подхватывает сессии ролей по событию `agent-preset/selected`,
но `roles` в строке плагина остаётся **ручным переопределением и главнее** автокарты.
Сейчас в `dsh-kanban/cordis.patch.yml` лежат три захардкоженных id:

```yaml
roles:
  reviewer: session-8b6b5c88-…
  verifier: session-3156d6d2-…
  dispatcher: session-fcf2bab8-…
```

Пока они там, автокарта не выигрывает никогда, а при пересоздании сессии роли id
стареют — то есть ровно та проблема, ради которой делали #031, остаётся.

Сделать: убрать блок `roles` из строки (или оставить пустым `roles: {}`), переписать
комментарий рядом — он до сих пор говорит, что id «нужно обновлять, когда роль
пересоздают в GUI». Проверить в живом профиле после перезапуска: карта ролей
появляется в `.kanban/.watcher-roles.json`, наряд уходит в сессию роли без ручных id.

## Критерии готовности
- [x] в `dsh-kanban/cordis.patch.yml` нет захардкоженных id ролей
- [x] комментарий описывает автокарту, а не ручное обновление
- [ ] в живом профиле после перезапуска карта ролей заполняется сама
- [x] `bin/test.sh` зелёный, зеркало awg совпадает

## Заметки
Найдено при проверке операционных последствий #031. `bin/install-kanban.sh`
перезаписывает строку из этого файла, так что правка едет вместе с набором.

## Сделано

Блок `roles` со тремя захардкоженными id убран из `dsh-kanban/cordis.patch.yml`,
комментарий переписан: сторож подхватывает роли сам по событию
`agent-preset/selected`, карта живёт в `.kanban/.watcher-roles.json`, а `roles`
остаётся ручным переопределением — и именно потому захардкоженные id в нём мешали
автоматике из #031.

Проверил, откуда живой профиль берёт строку: `~/.dsh/profiles/desktop/cordis.yml` —
пустой список записей, дерево собирается слоями («each bundle in package.json's
dsh.profile.bundles, then cordis.patch.yml»), поэтому патч-слой пакета и есть живая
строка, и правка вступает в силу при перезапуске профиля.

**Остаётся критерий, который без человека не проверить**: «в живом профиле после
перезапуска карта ролей заполняется сама». Отмечен как ожидающий перезапуска —
после него достаточно посмотреть `.kanban/.watcher-roles.json` и первый наряд роли.
