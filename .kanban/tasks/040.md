## Задача

Сделать рассылку нарядов автоматической: когда оркестратор назначает задачу,
исполнитель просыпается сам, без человека. Сейчас сторож будит только на
возвратах (`in-review`/`testing`/`ready`/`blocked` → `in-progress`), ревью,
тестах и `ready`; асайн из `backlog` никто не видит. Основание — спека
`.kanban/specs/001-backlog.md` (раздел «Наряды сторожа»).

**Приоритет:** это сейчас важнее #041 (обзор worktrees): без автоматического
асайна оркестратор не может разбудить исполнителя без человека.

Что сделать (файлы строго свои, см. границу):

1. Новый модуль `dsh-kanban/lib/backlog-notices.js` — чистые функции
   планирования двух новых нарядов (по образцу `planNotices` в
   `watcher-core.js`, но в отдельном файле):
   - **асайн:** карточка оказалась в `todo` с непустым `owner` — наряд этому
     владельцу: «тебе назначена #N «title», бери в работу:
     `bin/task-move.sh N in-progress --owner "$DSH_SESSION_ID" --role worker`;
     карточка: `.kanban/tasks/N.md`». Не будить, если та же карточка уже была в
     `todo` с тем же владельцем; новый наряд — только на появление карточки в
     `todo` с владельцем или на смену владельца в `todo`. Карточки в других
     статусах и `todo` без владельца нарядов об асайне не дают;
   - **пополнение:** в `todo` меньше `minTodo` — наряд роли `dispatcher`:
     «в todo N < min, пополни: `bin/backlog-fill.sh`». Минимум читать из
     `.kanban/board.json` (поле `minTodo`), нет файла или битый — дефолт 1;
     дедупликация по состоянию: один наряд на «недобор», повторно — только
     после того как `todo` вернулся к минимуму и снова упал ниже. Если в
     `backlog` нет карточек — в тексте честно сказать «backlog пуст: нужна
     нарезка спеки».
2. `dsh-kanban/lib/index.js` — минимальная проводка: после слияния снимка
   доски (этот файл уже умеет основной чекаут, worktrees сюда не входят)
   вызвать новые планировщики, доставку и запись состояния сделать тем же
   `deliverOnce`/`.kanban/.watcher-state.json`, что и остальные наряды. Роли
   берутся из той же карты (`roles.dispatcher`), минимум — из `board.json`.
   Ничего в существующей логике переходов не переписывать.
3. Новый тест `dsh-kanban/test/assignment.test.mjs` (стенд как в
   `delivery.test.mjs`: временная доска, поддельный `sessionController`), строка
   запуска в `bin/test.sh`. Обязательные случаи:
   - карточка в `todo` с владельцем → ровно один наряд владельцу; повторный
     обход/тик не дублирует; смена владельца в `todo` → новый наряд;
   - карточка `todo` без владельца, `backlog`-карточка, карточка в
     `in-progress` → нарядов нет;
   - `todo` ниже `minTodo` → один наряд диспетчеру; наряд не повторяется на
     каждом тике; после пополнения и нового недобора — новый наряд;
   - нет `board.json` → минимум 1; битый `board.json` → минимум 1, доска
     работает; роль `dispatcher` не задана → наряд пропускается без падения.
4. `bin/test.sh` — только строка запуска нового теста.

Не трогать: `dsh-kanban/lib/watcher-core.js`, `dsh-kanban/lib/client.js`,
`bin/task-move.sh`, `bin/task-new.sh`, `bin/board-status.mjs`, существующие
тесты, `KANBAN.md`, `AGENTS.md`, `package.json`. `watcher-core.js` сейчас
правится параллельно в #038 — это граница файлов, не пожелание. Документацию
(`KANBAN.md`, `AGENTS.md`) обновит оркестратор после слияния.

## Критерии готовности

- [ ] `bin/test.sh` зелёный, включая новый `assignment.test.mjs`.
- [ ] Живой стенд (временная доска, поддельный `sessionController`): карточка
      появляется в `todo` с владельцем → в поддельную сессию уходит ровно один
      наряд с id карточки и командой взятия в работу.
- [ ] Повторный тик без изменений второй наряд не отправляет (файл состояния).
- [ ] Смена владельца в `todo` даёт новый наряд; переход карточки в
      `backlog`/`in-progress` — не даёт.
- [ ] Недобор `todo` будит `dispatcher` один раз; после пополнения и повторного
      недобора — снова один раз.
- [ ] Тексты нарядов содержат id, путь к карточке и точную команду — как у
      существующих нарядов; при пустом `backlog` текст говорит про нарезку.
- [ ] Нет `board.json` → `minTodo` 1; битый JSON не роняет сторожа.

## Заметки

- Спека: `.kanban/specs/001-backlog.md`.
- **Почему отдельный модуль:** `watcher-core.js` занят задачей #038 (статус
  `backlog`), поэтому новая логика живёт в своём файле, а `index.js` только
  вызывает её. Так #038 и #040 идут параллельно без пересечения файлов.
- Минимум `minTodo` в `.kanban/board.json` заводит задача #039; #040 обязана
  работать и без этого файла (дефолт 1), поэтому зависимости по коду нет.
- Работаем в основном чекауте (`--no-worktree`).
- **Разбудить исполнителя без человека — цель этой задачи.** После её слияния
  оркестратор назначает карточку в `todo` и исполнитель просыпается сам; для
  живой проверки нужен один перезапуск приложения (хост-половина читается при
  старте профиля) — сделает оркестратор.
- Сдал в ревью — `bin/task-move.sh 040 in-review --role worker --tokens auto --note "..."`.
