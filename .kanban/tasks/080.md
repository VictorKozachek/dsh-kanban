## Зачем

12.11 плагин `dsh-memory` регистрировал инструменты `memory.search`,
`memory.write`, `memory.stats`, `memory.verify`, `memory.invalidate`. DeepSeek API
требует имя инструмента `^[a-zA-Z0-9_-]+$`, точка запрещена — запрос к модели
падал с `Invalid 'tools[32].name'`, сессия не отвечала. Ревьювер пропустил это
(проверял только код задачи), пришлось отключать плагины.

Нужно, чтобы ревьювер **основательно проверял такие ситуации** и не отдавал
задачу дальше, пока не убедился, что ничего не падает.

## Что сделать

1. **Персона ревьювера** (`agent-presets/reviewer/persona.txt` — источник, затем
   `bin/gen-role-presets.sh` перегенерирует `presets/role-presets.patch.yml` и
   `dsh-kanban/presets/role-presets.json`):
   добавить обязательный блок «Совместимость инструментов и плагинов»:
   - если задача трогает регистрацию инструментов/плагинов — проверить имена
     инструментов на соответствие `^[a-zA-Z0-9_-]+$` (никаких точек, слэшей,
     кириллицы);
   - проверить, что плагин/пакет загружается и не отключает инструменты;
   - сделать **smoke-запрос к модели** после включения плагина (или проверить
     `request/header`/лог сессии) и убедиться, что нет `INVALID_REQUEST`/
     `tools[...]` ошибок;
   - прогнать `bin/test.sh` (или целевые тесты) и проверить, что сессия
     открывается/отвечает;
   - если плагин внешний и проверить нельзя — вернуть задачу с конкретным
     воспроизведением и логом, а не «принято».
2. При необходимости — отдельный skill (пакет/каталог скилов) вместо только
   персоны; выбрать механизм по DSH (skill-filesystem/tool-skill) и подключить
   его в пресет ревьювера.
3. Тесты: сгенерированный JSON содержит новый блок; `bin/gen-role-presets.sh`
   идемпотентен; `bin/test.sh` зелёный.
4. Документация: `AGENTS.md`/`KANBAN.md` — что именно проверяет ревьювер при
   изменениях инструментов; пример ошибки `memory.*` → `Invalid 'tools[32].name'`.
