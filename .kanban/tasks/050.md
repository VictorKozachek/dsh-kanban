## Задача

Два долга, которые ревьювер и тестировщик #047 отметили как не блокирующие, но
которые стоит закрыть до живой приёмки фичи 002.

1. **Регрессия с настоящим скриптом.** В `dsh-kanban/test/card-actions.test.mjs`
   сценарий «реальный запуск скрипта» использует printf-заглушку вместо
   `bin/task-assign.sh`, поэтому контракт канала с настоящим скриптом в наборе не
   закреплён. Добавить прогон на временном git-репозитории по образцу тестов
   #046: `.kanban/tasks/*.md`, `.kanban/.workers.json`, настоящие
   `git worktree add`; канал (`assign`/`unassign`) должен:
   - асайнить карточку из `backlog` в `todo` с владельцем и `role worker`,
     коммитом карточки в ветке, если она живёт в рабочем дереве; основной
     чекаут не тронут;
   - возвращать бизнес-отказ на повторный асайн и на чужой статус;
   - отдавать код 4/ok:false, когда все заняты;
   - возвращать понятный отказ, если `bin/task-assign.sh` отсутствует.
   Скрипт запускать из настоящего пути (как в #046-тестах), а не из заглушки.
2. **Честная самопроверка канала при старте.** Сейчас `apply` в
   `dsh-kanban/lib/index.js` проверяет `Gateway.claimsEndpoint` слишком рано:
   gateway может быть ещё не смонтирован, кеш claims пуст — в логе появляется
   ложный warn «не объявил», хотя канал работает. Переделать пробу: выполнять
   после `ready`/`ready`-события (или через короткий `setTimeout` с уборкой по
   `dispose`) и разделить сообщения: «не проверено (gateway ещё не готов)» ≠
   «endpoint не объявлен» ≠ «видит endpoint». Тест на состояние пробы — по
   возможности юнит-тестом с поддельным gateway; если нельзя — зафиксировать в
   карточке ручную проверку по логу после рестарта.

Файлы задачи: `dsh-kanban/test/card-actions.test.mjs`,
`dsh-kanban/lib/index.js` (только блок самопроверки). Не трогать:
`dsh-kanban/lib/client.js` (это #048), `bin/*`, `AGENTS.md`, `KANBAN.md`.
