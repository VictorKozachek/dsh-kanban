## Задача
Две мелочи в `bin/sync-from-awg.sh` и его тестах, найденные при независимой
проверке #009:

1. **`--from` без значения** даёт `exit 1` с bash-сообщением про строку 32, а не
   `exit 2` с внятной подсказкой, как для неизвестной опции: `shift 2` выполняется
   при одном оставшемся аргументе. Проверять `$#` до `shift` — как сделано у
   остальных флагов набора.
2. **Тест «перенос убирает то, чего нет в источнике» опирается на `rsync --delete`**:
   на машине без rsync набор покраснеет, хотя сам скрипт ведёт себя как
   задокументировано — предупреждает и копирует без удаления лишнего. Либо
   пропускать эту проверку без rsync с явной пометкой, либо требовать rsync в шапке
   скрипта и в `KANBAN.md`.

## Критерии готовности
- [x] `--from` без значения → `exit 2` и понятная подсказка (регрессия)
- [x] поведение теста переноса без rsync определено: пропуск с пометкой **или**
      явное требование rsync в шапке и в документации
- [x] `bin/test.sh` зелёный

## Сделано

- `--from` проверяет наличие значения **до** `shift`: без значения — код 2 и понятная
  подсказка (`--from DIR`, по умолчанию `~/projects/awg`), как у остальных флагов
  набора. Раньше bash сообщал про строку 32 и выходил с кодом 1;
- поведение теста без `rsync` **определено**: удаление лишнего делает `rsync --delete`,
  поэтому без него проверка помечается пропуском («пропуск: удаление лишнего требует
  rsync (его нет в PATH)»), а не краснеет. Роль rsync записана в шапке скрипта: без
  него перенос предупреждает и копирует без удаления, то есть приёмник может
  сохранить файлы, которых в источнике уже нет;
- регрессия на `--from` без значения.
