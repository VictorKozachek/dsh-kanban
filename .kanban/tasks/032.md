## Задача
Следствие находки по #028: недоставленный наряд повторяется только при следующем
переходе этой же карточки. Стартовый обход объявляет лишь карточки, которые ждут
роль (`in-review`/`testing`/`ready`), а наряд «вернулась в работу» (адресован
владельцу) на старте не повторяется — сторож не отличает возврат от обычной работы
и молчит, чтобы не будить владельцев всех карточек в работе.

Практическое следствие: если сессию владельца пересоздали, наряд о возврате теряется
молча и карточка висит в `in-progress`.

Сделать так, чтобы недоставленные наряды запоминались в файле состояния и
повторялись при старте профиля (или чтобы владелец в `in-progress` объявлялся
точечно — по записи о неудачной доставке, а не по всем карточкам в работе).

## Критерии готовности
- [x] недоставленный наряд не теряется при перезапуске профиля
- [x] владельцы карточек, которые просто работают, не будятся
- [x] проверка доставки воспроизводит потерю и её отсутствие
- [x] AGENTS.md: граница, описанная в #028, обновлена

## Заметки
Причина — проверка тестировщика по #028 (стенд с падающим `sessionController`).

## Сделано

Неудачная доставка теперь оставляет след: наряд со своим текстом пишется в
`.kanban/.watcher-pending.json` (добавлен в `.gitignore`), а успешная доставка этот
след стирает. Следы, для которых наряд всё-таки дошёл, снимаются при загрузке.

При старте профиля сторож, кроме объявления карточек, которые ждут роль, повторяет
запомненные наряды — то есть наряд о возврате владельцу больше не теряется, если
сессию владельца пересоздали. Владельцы просто работающих карточек при этом не
будятся: повторяются только те наряды, доставка которых действительно не удалась.

Проверка воспроизводит и потерю, и её отсутствие: доставка падает (`agent-busy`) →
появляется файл недоставленных, файл состояния пуст; следующий запуск доставляет
наряд и записывает его; третий запуск не повторяет ничего.

`AGENTS.md`: граница из #028 переписана по факту — раньше там было сказано, что
наряд о возврате теряется молча.
