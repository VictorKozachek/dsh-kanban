## Задача (issue #4)

После рестарта DSH сессии с прерванным ходом остаются мёртвыми («Task stopped»).
DSH при `resume` сам досыпает `interruptedTurnClosers` (см. `dsh-agent-loop`
README), поэтому достаточно **на старте найти такие сессии и отправить prompt**.

### Состав

1. Вынести декодер лога (`splitFrames`, `decodeLog`, `openTurnOf`, `readLog`) из
   `bin/session-preset.mjs` в `dsh-kanban/lib/session-log.js`, CLI переключить на него.
2. `dsh-kanban/lib/resume.js`:
   - роли из `.kanban/.watcher-roles.json` наблюдаемых досок;
   - найти лог `$DSH_HOME/sessions/<cwd>/<uuid>/session.v4.jsonl.zstd`;
   - кандидат: `openTurn === true`, возраст последнего события в окне
     `[minAgeSeconds, maxAgeHours]`, не больше `maxSessions`;
   - prompt в очередь с текстом: ход прерван, проверить незавершённые tool calls,
     не повторять вслепую, продолжить по карточке/роли; для ждавших человека —
     «вопрос снят при перезапуске»;
   - dedupe `.kanban/.watcher-resume.json` (`sessionId + turnStartSeq`);
   - диагностика `resume-sent`/`resume-skipped`/`resume-failed`.
3. Конфиг `resume: { enabled, maxAgeHours=12, minAgeSeconds=60, maxSessions=5 }`.
   По умолчанию — выключено до боевого прогона.
4. Не будить subagent-owned/неизвестные сессии; permanent-ошибку писать в diag.
5. Тесты: лог с открытым ходом → prompt; закрытый ход/старый/свежий/выключено →
   skip; dedupe; ошибка prompt.

### Критерии

- [ ] После рестарта сессия с открытым ходом получает наряд-возврат один раз.
- [ ] Закрытые/старые/живые сессии не будятся; лимит N соблюдается.
- [ ] `resume.enabled=false` полностью выключает.
- [ ] Тесты и `bin/test.sh` зелёные; в диагностике видны причины skip.
