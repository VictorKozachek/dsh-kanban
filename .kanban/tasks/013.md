## Задача
В GUI не было видно ни одного пресета роли. Причина: в DSH 0.1.7 пресет — это
**строка композиции профиля** (`@deepseek-ai/dsh-agent-preset` с
`config.id/order/plugins`), а старый формат каталогом `~/.dsh/.agent-presets`
эта версия не читает вовсе. `bin/install-presets.sh` писал именно старый формат,
поэтому четыре роли лежали в каталоге, до которого приложению нет дела.

## Критерии готовности
- [x] четыре пресета ролей есть в композиции desktop-профиля (проверено офлайн:
      строки `preset-dispatcher/worker/reviewer/verifier`, порядок 10–13, по 19
      плагинов, персона наша, 0 предупреждений композиции)
- [x] генерация и установка воспроизводимы скриптами, без ручных правок
- [x] `bin/test.sh` зелёный в `awg` и в `m-future`
- [x] коммиты: `awg` 5d2d6f4, `m-future` 21f23fa
- [ ] проверить глазами в GUI: пресеты видны при создании сессии

## Что поправить (вернул ревьювер)
- [x] форма шаблона проверяется явно: генератор требует ровно один блок
      `- insert:` и ровно одну строку `prefix:`; негативные фикстуры на оба случая;
      артефакт сверяется со **встроенным** шаблоном (пересборка байт-в-байт)
- [x] установщик ловит ошибку записи и объясняет причину (профиль вне песочницы
      сессии) — без трейсбека; регрессия на недоступный патч-слой

## Сделано (раунд 2)

- **форма шаблона** проверяется явно в `bin/gen-role-presets.sh`: ровно один блок
  `- insert:` и ровно одна персона (`prefix:`), иначе остановка с объяснением, что
  форма встроенного файла изменилась. Это закрывает риск, из-за которого ревьювер
  и просил боевую фикстуру: молча собрать пресеты с чужим содержимым больше нельзя.
- **негативные фикстуры**: `test/fixtures/standard-two-inserts.patch.yml` и
  `standard-two-prefixes.patch.yml` — генератор обязан их отвергнуть (регрессии).
- **артефакт сверяется со встроенным шаблоном**: набор пересобирает
  `presets/role-presets.patch.yml` из шаблона приложения и сравнивает байт-в-байт;
  если приложения нет — проверка пропускается с пометкой. То есть боевой файл
  действительно участвует в регрессиях.
- **фикстура помечена как синтетическая** (`test/fixtures/standard.patch.yml`):
  она проверяет форму, а не боевой файл.
- **установщик** ловит ошибку записи в патч-слой и печатает две понятные строки
  (причина и что делать) вместо трейсбека; регрессия — на доступный только для
  чтения патч-слой. Тест сразу нашёл ошибку в самой правке: в питоновском блоке
  установщика не было `import sys`.
