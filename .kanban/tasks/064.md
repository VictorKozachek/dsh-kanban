## Задача

В DSH нельзя сменить пресет уже стартовавшей сессии — реестр пресетов жёстко
бросает `agent-preset/locked` при `lastTurn > 0` (проверено по коду 0.2.1-rc.3).
Из-за этого после потери пресетов (issue #1) остаётся только архив сессий.
Решение — **офлайн-инструмент**: при закрытом DSH досыпать в лог сессии событие
`agent-preset/selected` (лог append-only, один zstd-кадр на событие), и после
рестарта сессия поднимется с новым пресетом. Полное описание — `.kanban/specs/006.md`.

### Что сделать

1. **`bin/session-preset.mjs`** — логика на Node (`bin/node.sh`, `node:zlib`
   zstd): чтение v4-лога (конкатенация zstd-кадров, один JSON-объект на строку),
   определение `lastSeq`, досыпание одного кадра с
   `{"type":"agent-preset/selected","seq":lastSeq+1,"time":Date.now(),"data":{"agentPreset":…}}`,
   обратное чтение для проверки, бэкап/restore, обновление
   `.kanban/.watcher-roles.json` (поиск ближайшей доски от cwd сессии; роль —
   по `--role` или по имени пресета для четырёх ролей; `--no-roles`).
2. **`bin/session-preset.sh`** — CLI-обёртка:
   `--list`, `--session <id|prefix>`, `--cwd DIR`, `--all`, `--from <preset>`,
   `--to <preset>`, `--role <role>`, `--dry-run`, `--backup`, `--restore FILE`,
   `--allow-unknown`, `--force`, `--no-roles`, `--yes`, `--json` (по желанию),
   `-v`; коды 0/1/2. Отказы: DSH запущен (живой pid из SingletonLock), лог не
   v4/битый, неизвестный пресет (id должен быть среди
   `presets/role-presets.json`), открытый ход (`turn/start` без `turn/end`) —
   только с `--force`. В конце — «перезапустите DSH».
3. **Тесты.** `dsh-kanban/test/session-preset.test.mjs` на синтетических
   v4-логах: досыпание, seq/time, обратное чтение, dry-run не меняет файл,
   бэкап, отказ при неизвестном пресете/битом логе/открытом ходе, обновление
   карты ролей на временной доске; CLI-коды и `--list` — в
   `bin/test-scripts.sh` (без живого DSH: проверяем отказ при «запущенном» на
   подставном pid/или через отдельный флаг). Добавить запуск node-теста в
   `bin/test.sh`.
4. **Документация.** `KANBAN.md`: раздел «Смена пресета существующей сессии
   (офлайн)» (зачем, как, ограничения: рестарт обязателен; DSH API это не
   разрешает; для восстановления после потери пресетов достаточно обновления
   плагина — #062; «model-visible ⟺ logged» — менять осознанно, между ходами) +
   строка в «Диагностике»; `README.md` — короткий абзац. Плюс строки новых
   файлов в таблицу «Что лежит в проекте» (`bin/session-preset.sh`,
   `bin/session-preset.mjs`, `dsh-kanban/test/session-preset.test.mjs`) — иначе
   проверка набора покраснеет.

## Критерии готовности

- [ ] `--list` и dry-run показывают сессии/cwd/текущий пресет; реальный прогон
      меняет копию (проверить на копии лога, не на живой сессии).
- [ ] Лог после правки декодируется; оригинальные кадры не тронуты; бэкап есть;
      `--restore` возвращает файл.
- [ ] Отказы: DSH запущен, неизвестный пресет, битый лог, открытый ход.
- [ ] Карта ролей доски обновляется (и `--no-roles` её не трогает).
- [ ] `bin/test.sh` зелёный (в т.ч. чистом клоне); число проверок — в заметке.
- [ ] Документация и строки таблицы файлов на месте.
