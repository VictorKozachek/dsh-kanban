## Задача

GitHub issue #1: обновление плагина ломает существующие сессии (пресеты
«слетают» в стандартные, сторож не может слать наряды, смена пресета непустой
сессии невозможна → архивирование всего парка). Спека — `.kanban/specs/005.md`.

Причина: id пресета хранится в логе сессии, DSH при рестарте берёт **текущее
определение** этого id и «rejects a missing definition», а наши определения живут
в профильном патче (`bin/install-presets.sh`), который обновление/сброс профиля
может потерять. Лечим тем, что определения пресетов регистрирует **сам плагин**
при старте — дубликаты с legacy-строками терпим.

### Что сделать

1. **Артефакт.** `bin/gen-role-presets.sh` дополнительно генерирует
   `presets/role-presets.json`: массив из 4 определений
   `{ id, name, description, order, plugins }` (id = `dispatcher`/`worker`/
   `reviewer`/`verifier`, order 10/11/12/13; поля — из `preset.yml`/`persona.txt`,
   как в YAML-артефакте). YAML-тег `!!js expr` в JSON — узел
   `{ "__jsExpr": "expr" }` (штатная форма entry-list диалекта; загрузчик
   интерполирует её рекурсивно — проверено по `cordis-plugin-loader`).
   Генерация может требовать `python3` (+PyYAML) — если его нет, понятная
   ошибка с подсказкой.
2. **Регистрация при старте.** Новый `dsh-kanban/lib/presets.js`:
   - читает `presets/role-presets.json` относительно пакета (host-половина
     работает из пакета плагина; путь резолвить от `import.meta.url`, не от cwd);
   - функция `registerRolePresets({ agentPresets, log })`: для каждого
     определения `await agentPresets.register(def)`; на ошибку
     `Duplicate agent preset: …` — `log("warn", …)` и продолжить (legacy-строки
     профиля уже зарегистрированы — это нормально); другие ошибки — тоже не
     валить плагин, а записать в лог; возвращает `dispose()`.
   - в `dsh-kanban/lib/index.js`: добавить `agentPresets` в `inject` (сейчас там
     только `sessionController`), в `apply` вызвать регистрацию через
     `ctx.effect`, чтобы выгрузка плагина снимала определения; вызывать **до**
     старта сторожа; повторный dispose идемпотентен.
3. **Тесты.**
   - `dsh-kanban/test/presets.test.mjs` (новый): фейковый `agentPresets`
     (`register` пишет вызовы; смоделировать ошибку-дубликат): регистрируются
     все 4; при дубликате — не падает и продолжает; dispose снимает регистрации
     в обратном порядке; ошибка чтения JSON даёт понятную диагностику, а не крэш;
     JSON-артефакт валиден (id/order/plugins, есть `__jsExpr`-узлы).
   - в `bin/test.sh` добавить запуск нового теста.
   - интеграционно: в `bin/host-shutdown-check.mjs` — сценарий/флаг
     `--no-presets` (или отдельная проверка), где профиль харнесса **без**
     preset-строк, плагин поднимается и `agentPresets` содержит 4 роли; при
     наличии preset-строк в профиле — старт не падает от дубликатов. Бюджеты
     harness (ack 5 с / exit 10 с) не нарушать.
4. **Таблица файлов.** В `KANBAN.md` разрешено добавить только строки новых
   файлов (`dsh-kanban/lib/presets.js`, `dsh-kanban/test/presets.test.mjs`,
   `presets/role-presets.json`) в таблицу «Что лежит в проекте».

Файлы задачи: `bin/gen-role-presets.sh`, `dsh-kanban/lib/presets.js` (новый),
`dsh-kanban/lib/index.js`, `presets/role-presets.json` (новый, генерируемый),
`dsh-kanban/test/presets.test.mjs` (новый), `bin/test.sh`, `bin/host-shutdown-check.mjs`,
