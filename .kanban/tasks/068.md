## Симптом (со слов пользователя)

Чтобы сторож поднялся после перезапуска и снова начал раздавать наряды, приходится
запускать приложение из терминала:

```bash
"/Applications/DeepSeek Harness.app/Contents/MacOS/DeepSeek Harness" 2>&1 | tee /tmp/dsh.log
```

При обычном запуске (Finder / `open -a`) host-половина не раздаёт наряды, хотя
клиентская половина (вкладка доски) работает. Ранее это же наблюдалось в #2:
после рестарта наряды не шли, пока не перезагрузить строку плагина через
`pluginManager/setPluginEnabled` (HMR) — то есть подозрение на **порядок
инициализации при холодном старте**, а не на логику сторожа (после reload всё
работает).

## Гипотезы (проверить по диагностике холодного старта)

1. **Профильный оверрайд строки** `~/.dsh/cordis.patch.yml` содержит
   `- id: ui-kanban` + `config:` без `name: dsh-kanban`; документация DSH про
   override слоёв говорит перечислять поля строки. Если при холодном старте
   оверрайд не сливается с bundle-строкой, entry может активироваться без
   модуля/не активироваться вовсе (а HMR-reload это маскирует).
2. **Порядок применения (inject)**: `apply` зависит от `sessionController` +
   `agentPresets`; если холодный старт даёт apply с пустым/частичным конфигом
   или до готовности сервисов — сторож не стартует. Запись `applies[].config`
   покажет.
3. **stdout-зависимость**: терминальный запуск даёт открытый pipe stdout;
   обычный — закрытый. Если host-половина что-то пишет в `process.stdout`
   без защиты, запись может ронять инициализацию (в нашем коде `log()` и
   диагностика защищены, но проверить стоит).

2. По результату: если `applies` есть, но `boards=0`/`error` — починить
   инициализацию; если `applies` пуст — entry не активируется, чинить
   оверрайд/порядок (добавить `name` в patch-строку, проверить на чистом
   профиле через harness).
3. **Самолечение**: после `apply` проверять, что `watchers.length > 0`;
   если пусто — планировать повторную инициализацию сторожа с коротким
   backoff (1–2 попытки) и писать это в диагностику. Осторожно с dispose.
4. **Тест**: harness с профилем, имитирующим оверрайд без `name` и с
   холодным стартом (host поднимается, плагин активен, сторож раздаёт наряд).
5. Документация: «после перезапуска не приходят наряды» → диагностика →
