## Задача
Правило «нераспределённую карточку не берут» держалось только протоколом.
`bin/task-move.sh` теперь отказывает в переходе `todo` → `in-progress`, если
`owner` пуст, указывает на другую сессию или исполнитель не назван вовсе.
Обход — `--force`; сообщение отказа печатает готовую команду закрепления.

## Критерии готовности
- [x] карточка с `owner: ""` не берётся, отказ с понятным сообщением
- [x] карточка, закреплённая за другим id, не берётся
- [x] владелец берёт свою карточку без `--force`
- [x] `--force` выполняет переход (осознанный обход)
- [x] регрессии: без `--owner`, незакреплённая, чужак, `--force`
- [x] документация согласована: `.kanban/tasks/README.md`, `AGENTS.md`,
      скил `kanban`, строка в «Диагностике» KANBAN.md
- [x] `bin/test.sh` зелёный

## Что поправить (вернул ревьювер)
- [x] обход правила в два шага: смена владельца чужой карточки теперь требует
      `--force`, сценарий «украсть в два шага» отвергается
- [x] подсказка печатает текущий статус (`${current:-todo}`); с сужением guard до
      очереди неверная команда для `blocked` стала невозможной в принципе
- [x] сначала проверяется допустимость перехода, потом владелец: `merged →
      in-progress` отвечает «недопустимый переход»
- [x] `field_of` снимает экранирование `yaml_value`: owner `a"b` берёт свою карточку
- [x] регрессии: перезапись чужого владельца, свой владелец, fallback на
      `$DSH_SESSION_ID`, owner с кавычкой, порядок проверок
- [x] возврат карточки чужой ролью — исправлено в `0b5bc38`: guard теперь касается
      только взятия из очереди
