## Задача

Два мелких долга из тестирования #050 (отмечены как не блокирующие, но повторены
и ревьювером). Код фичи не меняется, поведение не меняется.

1. **Регрессия на жизненный случай самопроверки.** В наборе нет юнит-теста на
   «gateway смонтировался между `apply` и пробой» — самый частый случай старта:
   проба идёт по `catchUpMs`, gateway успевает появиться, в логе должно быть
   ровно `info` «видит endpoint», без `warn`. Добавить в
   `dsh-kanban/test/card-actions.test.mjs` сценарий на настоящем `apply` с
   поддельным ctx: probe-таймер срабатывает после монтирования gateway (как в
   стенде тестировщика #050) → info без warn, `claimsEndpoint` вызван, по
   `dispose` таймер снят.
2. **Уровень лога «не проверено».** Сейчас «gateway ещё не готов» пишется как
   `warn`, и оркестратор может принять это за поломку. Понизить до `info` (текст
   уже честный), оставив `warn` только для настоящего «endpoint не объявлен».
   Проверить в тесте: три состояния — «видит» (info), «не проверено» (info),
   «не объявлен» (warn).

Файлы задачи: `dsh-kanban/test/card-actions.test.mjs`,
`dsh-kanban/lib/index.js` (только уровень лога в блоке самопроверки). Не трогать:
`dsh-kanban/lib/client.js`, `bin/*`, `AGENTS.md`, `KANBAN.md`.
