## Задача (M1)

Синхронизация локальных карточек с хабом из плагина (#071), без изменения UI.

### Состав

- Конфиг строки плагина: `sync: { hubUrl, project, token, instanceId }`
  (по умолчанию выключено).
- Клиент синка в `dsh-kanban/lib/sync.js`:
  - читает свои карточки `.kanban/tasks/*.md` (home cards), считает хэш/версию;
  - **outbox** `.kanban/.sync/outbox.jsonl` (opId ULID, cardId, baseRev, payload)
    — переживает падение/офлайн;
  - фоновая отправка с backoff/jitter; `409` → перечитать карточку, не затирать;
  - pull по курсору `seq`; чужие карточки складывает в
    `.kanban/.sync/remote/<instance>.json` (пока без UI);
  - heartbeat инстанса и продление lease;
  - никогда не пишет чужие карточки в `.kanban/tasks`.
- CLI для проверки: `bin/kanban-sync.sh --once/--status` (обёртка над модулем).
- Тесты: мок-хаб (http server) — push/pull, ретрай после ошибки, дедуп opId,
  поведение при недоступном хабе (outbox растёт, данные целы).

### Критерии

- [ ] Два инстанса (разные `DSH_HOME`/проекты) через один хаб видят карточки
      друг друга в `.kanban/.sync/remote/`.
- [ ] Хаб выключен 30 минут: локальная работа идёт, после включения — догон,
      ни одна операция не потеряна и не задвоена.
- [ ] `409` не затирает более новую версию.
- [ ] Файловый режим без `sync` работает как раньше (тесты зелёные).

Файлы: `dsh-kanban/lib/sync.js`, `dsh-kanban/test/sync.test.mjs`,
`bin/kanban-sync.sh`, конфиг. Не трогать: `hub/` (M0), UI доски (M2).
