## Задача
В разделе «Границы» написано, что непроверенным остаётся поведение HMR. По
наблюдениям этой сессии поведение такое: правки клиентского бандла подхватываются
при обновлении страницы; правки `cordis.patch.yml` профиля применяются живьём
(watcher профиля); host-код требует перезапуска профиля. Заменить абзац на
фактическое поведение.

## Критерии готовности
- [x] раздел «Границы» больше не заявляет HMR непроверенным
- [x] описано, что применяется без рестарта, а что требует обновления страницы
      или перезапуска профиля
- [x] в «Диагностике» есть строка «правки клиента не видно → обновите страницу»
- [x] формулировки не противоречат проверкам: `bin/test.sh` зелёный

## Заметки
Заодно пройтись по другим утверждениям ранних прогонов: число колонок, число
пресетов, состояние установки — часть уже поправлена, стоит убедиться, что
не осталось устаревших.

## Сделано

- раздел «Границы» больше не говорит про непроверенный HMR: вместо него три
  проверенных факта — патч-слой профиля читается живьём, клиентский бандл
  подхватывается обновлением страницы (F5), host-код и строка плагина читаются
  при старте профиля (сторож доски и роль тестировщика заработали только после
  перезапуска);
- в «Диагностику» добавлены четыре строки: правки клиента не видно → F5; host-код
  не действует → перезапуск; сторож не разбудил роль → перезапуск и id сессий в
  `roles`; сторож объявил наряд дважды → версия карточки в ключе доставки;
- прошёлся по другим утверждениям ранних прогонов: число колонок (семь) и число
  пресетов (четыре) в документе верны, устаревших формулировок не осталось;
- формулировка про «рабочее дерево чистое» заменена на «набор в main», чтобы не
  противоречить чужим незакоммиченным правкам в проекте.
