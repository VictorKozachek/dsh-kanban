## Задача
Карточки 006, 007, 009 и 013 — инфраструктура самого набора, и их работа сделана
прямо в `main` обоих репозиториев, без ветки задачи. По протоколу же после
`testing` идёт `ready`, а закрывает карточку только `bin/task-commit.sh`, который
мержит ветку `task/<id>`. Ветки нет — значит карточку не закрыть штатно: она
застрянет в `ready`, а `--force` обесценит правило «сливает только оркестратор».

Нужно решение: либо у `task-commit.sh` появляется штатный путь «работа уже в
main» (например `--no-merge` с обязательной заметкой), либо такие задачи обязаны
идти через worktree, как все остальные.

## Критерии готовности
- [x] выбран вариант и записан в `AGENTS.md` и `KANBAN.md`
- [x] карточку, чья работа уже в `main`, можно закрыть одной командой, и это не
      `--force` вслепую: команда требует объяснения, почему слияния нет
- [x] есть тест на новый путь закрытия
- [x] `bin/test.sh` зелёный; поведение `ready → merged` для обычных задач не
      изменилось

## Заметки
Обнаружено при попытке закрыть #009 и #013. Связано с #011 (возврат карточки
чужой ролью): там та же природа — правило строже реальных сценариев.

Пока карточка открыта: задачи набора делать прямо в `main` и закрывать через
`--force` с объяснением в заметке (осознанный обход, а не тихий).

## Сделано
Выбран вариант владельца: режим у того же скрипта, чтобы «в merged только через
`task-commit.sh`» осталось правдой.

- `--no-merge` требует `--reason`: без причины отказ с подсказкой
- при существующей ветке `task/<id>` режим отказывает — это обычное слияние
- причина пишется в карточку заметкой «закрыто без слияния: …»
- проверка наличия ветки добавлена и в обычный режим, и в `--dry-run`: раньше
  dry-run печатал план и выходил 0, даже когда ветки нет — та самая тишина,
  из-за которой #006 выглядела «готовой к слиянию»
- чистое дерево требуется только для слияния: у `--no-merge` слияния нет
- шесть регрессий в `bin/test-scripts.sh`; `AGENTS.md` и `KANBAN.md` дополнены

Проверено на живой задаче: `bin/task-commit.sh 006 --no-merge --reason "…"`
закрыл #006 без merge-коммита. Коммиты: `m-future` 52051f3,
`awg` d2ceaf6.
