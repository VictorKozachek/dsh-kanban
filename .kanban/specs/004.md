# Спека 004: Дочерние доски: обзор досок дерева команд

Статус: активна (нарезана на задачи #059–#061).

## Зачем

Компания — это иерархия команд: `backend` → `agents` → `ai-manager`, и у каждой
команды свой проект со своей доской. Доски могут образовывать дерево и внутри
проекта: пример — `ai-fabric/aif-project`, где под корнем живут **37 досок** на разных
уровнях, включая реальную иерархию команд `backend/agents/ai-manager`,
`backend/agents/ai-engineer`, `backend/agents/ai-rop`, а также
`infra/k8s`, `frontend/web-console`, `voice/rt-gateway`, `docs/adr`…

Сейчас сессия видит только доску своей рабочей директории: `.kanban/tasks` своего
workspace плюс свои worktree. Родительская команда (менеджер `backend`, тимлид
`agents`) не видит, как идут задачи у дочерних проектов, — приходится открывать
каждую сессию отдельно.

Решение: **read-only обзор дочерних досок** в отдельной вкладке плагина —
агрегированная сводка по дереву досок и drill-down в доску ребёнка без права
записи.

## Требования

- [ ] **Вкладка «Дочерние доски»** в правом сайдбаре — второй таб плагина рядом с
      «Канбан» (свой `id`, заголовок, запись в гид). Работает в любой сессии:
      берёт манифест из рабочей директории этой сессии.
- [ ] **Манифест** `.kanban/children.json` в корне рабочей директории родительской
      сессии:
      ```json
      { "version": 1,
        "boards": [
          { "path": "aif-project/infra" },
          { "path": "aif-project/frontend", "title": "frontend" },
          { "path": "/Users/victor/projects/other-project" }
        ] }
      ```
      Относительные пути резолвятся от корня workspace сессии, абсолютные — как
      есть (доски вне дерева). `title` необязателен: по умолчанию последний
      сегмент пути.
- [ ] **Скрипт `bin/board-children.sh`** — генерация манифеста:
      ```bash
      bin/board-children.sh --root aif-project            # обойти дерево, записать ./.kanban/children.json
      bin/board-children.sh --root aif-project --print    # показать, не писать
      bin/board-children.sh --root . --depth 6 --out DIR/.kanban/children.json
      bin/board-children.sh --root aif-project --board /abs/other   # + внешняя доска
      ```
      Сканирует `--root` на каталоги с `.kanban/tasks` (глубина по умолчанию 4,
      `--depth N`), пропускает `.git`, `.idea`, `node_modules`, `worktrees`,
      `.worktrees` и скрытые каталоги; пути пишет относительными от `--root` и
      сортирует; повторный запуск идемпотентен. `--print` — только вывод. Коды:
      0 — ок, 2 — неверные аргументы или несуществующий `--root`, 1 — не удалось
      записать.
- [ ] **Host-служба `kanbanChildren`** (Typert remote, по образцу
      `kanbanCardActions`): аргумент `{ request: { sessionId } }`; читает манифест
      из cwd сессии, для каждой доски собирает снимок (`<board>/.kanban/tasks/*.md`
      плюс `<board>/worktrees/*/.kanban/tasks/<id>.md` — та же логика слияния
      «одноимённая карточка, свежесть `updated`», что у сторожа: переиспользовать
      чистые функции `watcher-core`), возвращает
      `{ ok: true, value: { boards: [{ path, title, cards, problems }], problems } }`.
      **Только чтение**: никаких операций записи и канала асайна; ошибка одной
      доски не валит остальные (попадает в её `problems`). Контракт ответа
      стабильный — клиент не зависит от деталей ФС.
- [ ] **Клиент:** вкладка показывает список досок (дерево по путям с отступами):
      - счётчики карточек по статусам (`backlog`, `todo`, `in-progress`,
        `in-review`, `testing`, `ready`, `blocked`);
      - карточки «в работе» (`in-progress`) с id, названием, владельцем/ролью и
        временем обновления;
      - ошибки чтения доски отдельной строкой;
      - клик по доске — **read-only** вид её колонок с карточками; клик по
        карточке — детали (описание, токены, роль/владелец, spec) без действий;
      - опрос раз в 3 с и кнопка ⟳; пустые состояния: нет манифеста → подсказка с
        командой `bin/board-children.sh`; досок нет; ошибка Remote — баннер.
- [ ] **Read-only явно:** у вкладки нет drag&drop, кнопок перевода и тоста
      «переношу…»; служба не принимает изменяющих аргументов. Родитель смотрит,
      но не управляет — асайн и переходы остаются у ролей дочерней доски.
- [ ] **Тесты:**
      - host-логика на временном дереве: разбор манифеста, слияние карточек с
        worktree, доска только в ветке, битая запись/нет доски, две доски
        независимы, счётчики;
      - рендер вкладки в поддельном cordis-контексте (как `render.test.mjs`):
        список досок, счётчики, drill-down, пустые состояния — и проверка, что
        элементов переноса и кнопок нет;
      - скрипт — в `bin/test-scripts.sh` на временном дереве (вложенность,
        `--depth`, пропуски `.git`/`worktrees`/`node_modules`, относительные и
        абсолютные пути, идемпотентность, `--print`, коды 0/1/2).

## Вне скоупа

- запись в доски детей, асайн, слияние и любые переходы за детей;
- наряды/эскалации родителю о событиях у детей (отдельная фича);
- изменение host-сторожа и его правил (`boards`/`roots`, роли, доставка);
- авторизация и права ролей. Read-only — гарантия UI и службы, **не песочница**:
  если доски детей лежат внутри workspace родителя, родительская сессия физически
  может писать в них bash'ем; для жёсткой изоляции держите dashboard-воркспейс вне
  дерева детей (чтение по абсолютным путям работает).

## Замечания

- Хост читает файловую систему без песочницы, поэтому обзор работает и для досок
  вне workspace родителя (листинг из клиента там запрещён, но чтение — нет;
  листинг здесь делает host-служба).
- Манифест с относительными путями переносим и может лежать в git; абсолютные
  пути машинно-зависимы.
- Роль родительской сессии (`dispatcher`) остаётся при её собственной доске —
  наряды по доскам детей родителю не приходят (вне скоупа).
