# Спека 006: Смена пресета существующей сессии — офлайн-инструмент

Статус: активна (продолжение issue #1; нарезана на задачу #064).

## Зачем

В DSH **нельзя** сменить пресет уже стартовавшей сессии: это жёстко
заблокировано в реестре пресетов. В интерфейсе выбор доступен только пустой
(blank) сессии. Из-за этого после потери определений пресетов (issue #1) или
любого «слетания» роли пользователь может только архивировать сессии — на
инфраструктуре с сотнями проектов это неприемлемо.

Нужен инструмент, который позволяет **осознанно сменить пресет существующей
сессии** (одной или массово) без архивирования, с бэкапом и понятными
ограничениями, и обновляет при этом карту ролей доски.

## Что подтверждено кодом DSH 0.2.1-rc.3

1. `agentPresets.select(agent, id)` **сам** проверяет blank: если
   `turnBoundary.openTurnStartSeq !== null` или `lastTurn > 0` — бросает
   `RemoteError("agent-preset/locked", "This session has already started")`
   (`dsh-agent-preset-registry/lib/index.js`). Это не UI-ограничение, обойти
   через штатный API нельзя.
2. **Лог сессии append-only** (`dsh-session-persistence-jsonl/README`):
   `session.v4.jsonl.zstd` — конкатенация независимых zstd-фреймов: первый кадр —
   заголовок (`{type:"session", version:4, id, createdAt, cwd, agentPreset, …}`,
   заморожен как факт создания), далее **один кадр на батч событий** (сейчас —
   одно событие на строку). Записанные события никогда не переписываются.
   Torn-кадр в хвосте: валидные строки читаются, битые отбрасываются.
3. **Текущий пресет — проекция `agentPreset`**, инициализируется из заголовка и
   продвигается событием `{"type":"agent-preset/selected","seq":N,"time":ms,
   "data":{"agentPreset":"<id>"}}`. Проверено на реальных логах: у сессии-
   исполнителя заголовок `standard`, а событие `seq:3` ставит `worker`.
4. Значит смена пресета **офлайн** законна и консистентна: при закрытом DSH
   досыпать в лог один zstd-фрейм с событием `agent-preset/selected`
   (`seq = lastSeq + 1`), при следующем старте DSH соберёт сессию по новой
   проекции. Правило «model-visible ⟺ logged» соблюдено — решение записано в
   лог. Прототип на копии реальной сессии: кадр досыпается, читается обратно как
   одна JSON-строка.

## Дизайн инструмента

`bin/session-preset.sh` (CLI) + `bin/session-preset.mjs` (логика на Node, zstd
из `node:zlib`; тот же `bin/node.sh`), для пользователей и для массовой миграции.

```bash
bin/session-preset.sh --list                         # сессии, cwd, текущий пресет
bin/session-preset.sh --session <id|prefix> --to worker
bin/session-preset.sh --cwd DIR --from standard --to worker
bin/session-preset.sh --all --from standard --to worker --dry-run
bin/session-preset.sh --session <id> --to worker --backup     # бэкап лога
bin/session-preset.sh --restore <backup-файл>
```

Требования:

1. **Безопасность.** Отказываться, если DSH запущен (живой pid из
   `SingletonLock`), если файл сессии не читается/не v4, если цель неизвестна
   (id должен быть среди `presets/role-presets.json` или `--allow-unknown`),
   если последний ход не закрыт (`turn/start` без `turn/end`) — предупреждать и
   требовать `--force`. Бэкап перед правкой (по умолчанию в
   `~/.dsh/session-backups/<id>.<ts>.zst`) и проверка после: перечитать лог,
   убедиться, что последняя строка — наше событие с нужным `data`.
2. **Точность.** `seq = lastSeq + 1`, `time = Date.now()`; досыпается ровно один
   zstd-фрейм (не перезапись), как это делает сам DSH; оригинальные кадры не
   трогаются.
3. **Карта ролей доски.** После смены пресета сессия должна снова попадать в
   `.kanban/.watcher-roles.json` своей доски (сторож заполняет карту по **живым**
   событиям выбора пресета; офлайн-событие при рестарте не эмитится). Инструмент
   находит доску по cwd сессии (ближайший родитель с `.kanban/`) и, если просили
   роль (`--role` или автоматически по имени пресета для ролей
   dispatcher/worker/reviewer/verifier), обновляет файл после подтверждения;
   `--no-roles` — не трогать. Поведение задокументировать.
4. **Массовость и предсказуемость.** `--dry-run` печатает план (сессия, cwd,
   from→to, обновление роли), `--yes`/интерактивное подтверждение, `-v`.
   Вывод в конце: «перезапустите DSH, чтобы изменения вступили в силу».
5. **Тесты.** `dsh-kanban/test/session-preset.test.mjs` на синтетических v4-логах
   (заголовок + события): досыпание события, `seq`/`time`, чтение обратно,
   dry-run не меняет файл, бэкап создаётся, отказ при неизвестном пресете/битом
   файле/открытом ходе, обновление карты ролей на временной доске; CLI-коды
   (0/1/2) — в `bin/test-scripts.sh`. Регрессия: после «смены» лог читается
   штатным декодером (наши тесты декодируют кадры сами, как в `bin/session-preset.mjs`).
6. **Документация.** `KANBAN.md`/`README.md`: раздел «Смена пресета существующей
   сессии (офлайн)» — зачем, как, ограничения (нужен рестарт; DSH API это не
   разрешает; для восстановления после потери пресетов достаточно обновления
   плагина — #062), и предупреждение про «model-visible ⟺ logged» (менять только
   осознанно, между ходами). Диагностика issue #1 ссылается сюда как на «аптечку».

## Вне скоупа

- Живая смена пресета без рестарта: невозможна без изменения DSH (реестр бросает
  `agent-preset/locked`). Отдельно можно оформить feature request в upstream DSH:
  разрешить смену пресета **idle**-сессии между ходами (проекция уже
  event-sourced, осталось продуктовое решение).
- UI-кнопка в нашей вкладке: возможна позже как обёртка над этим CLI; сейчас
  достаточно CLI (и не нужно тащить это в канбан-таб).
- Массовая миграция чужих пресетов/кастомных определений.

## Критерии готовности

- [ ] `--list`, одиночный и массовый режимы работают по dry-run и реально.
- [ ] Смена пресета на копии реального лога: после правки файл декодируется,
      проекция читается как новая; оригинальные кадры не тронуты.
- [ ] Отказы: DSH запущен, неизвестный пресет, битый лог, открытый ход.
- [ ] `--restore` возвращает лог из бэкапа; бэкап по умолчанию создаётся.
- [ ] `bin/test.sh` зелёный, новые тесты и CLI-проверки включены.
- [ ] Документация: раздел + ограничения + ссылка из диагностики.
