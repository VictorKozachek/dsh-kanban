# Спека 002: Человек в цикле: drag&drop backlog↔todo с автоасайном

Статус: принята, нарезана на задачи #046–#049.

## Зачем

Оркестратор нарезает задачи в `backlog`, и очередь живёт сама: сторож сигналит о
недоборе, `backlog-fill` выдаёт по FIFO. Но человеку негде вмешаться: захотел
поднять конкретную задачу вперёд — нужен чат с оркестратором и скрипты. Фича даёт
человеку прямо в доске перетащить карточку `backlog → todo` (и вернуть
`todo → backlog`) — и асайн на самого свободного исполнителя с нарядом, как если
бы это сделал оркестратор. Никаких обходов протокола: меняются только
`backlog`/`todo`, остальные переходы по-прежнему делают роли.

## Решения (согласованы с человеком)

1. **Какие перемещения.** Только `backlog ↔ todo` и только руками человека.
   Вперёд — `backlog → todo` с асайном; назад — `todo → backlog`, только из
   `todo` (карточку в `in-progress` человек увести не может: исполнитель уже
   работает). Все остальные колонки — только агенты по протоколу.
2. **«Самый свободный».** Нагрузка исполнителя — число карточек, которые за ним
   числятся в конвейере: `in-progress + in-review + testing` (по слитому снимку
   доски, с учётом рабочих деревьев). Меньше всего — свободнее; равенство решает
   порядок `.kanban/.workers.json` (fallback — единственный `worker` из
   `.kanban/.watcher-roles.json`).
3. **Все заняты.** Если ни один исполнитель не свободен (у каждого есть
   `in-progress`) — перемещение **отклоняется**, карточка остаётся в `backlog`,
   человек видит понятное сообщение. Никаких «в очередь поверх работы».

## Архитектура

Клиентская половина плагина умеет только читать (`workspaceFiles.list/read/stat/
changes` — записи там нет), поэтому движение карточки идёт через host-половину:

- **`bin/task-assign.sh <id>`** — асайн конкретной карточки: выбрать свободного с
  минимальной нагрузкой, перевести `backlog → todo` с владельцем. Режим
  `--unassign` — вернуть `todo → backlog` (снять владельца и роль).
  `--dry-run` — показать план. Скрипт одинаково работает с карточкой в основном
  чекауте и в рабочем дереве (переход и коммит — там, где лежит карточка), и с
  тем же слиянием копий по свежести `updated`, что у сторожа и `backlog-fill`.
- **Командный канал клиент → хост** — спайк и реализация (задача #047):
  в приоритете свой host-remote по образцу `remote.workspaceFiles`; если на
  текущей версии DSH это не взлетает — переиспользовать существующий remote
  (например, выполнить скрипт через терминальный контроллер); деградация —
  промпт оркестратору. Задача обязана зафиксировать, какой путь выбран и почему.
- **Клиент** (задача #048): drag&drop карточек между `backlog` и `todo`, плюс
  кнопка-дубль для доступности и на случай сложностей с DnD в мини-рендерере;
  после успеха — перечитать доску, при отказе — сообщение («свободных нет»,
  «карточка уже в работе»).
- **Сторож** уже умеет будить исполнителя нарядом асайна (#040): как только
  карточка с владельцем появится в `todo`, исполнитель проснётся сам.

## Протокол (дополнение к AGENTS.md)

- Человек может двигать только `backlog ↔ todo`; асайн всегда идёт через
  `bin/task-assign.sh`, а не ручной правкой карточки.
- `todo → backlog` допустим только из `todo`; снимаются `owner` и `role`.
- Ручной асайн не отменяет правил: одна карточка в `in-progress` на агента,
  асайн только свободному, лимит в работе 3 — их держат и сторож, и скрипт.
- Документацию протокола (`AGENTS.md`) обновляет оркестратор после слияния;
  остальные доки — задача #049.

## Приёмка (живой сценарий)

1. В `backlog` есть 2–3 карточки, `todo` недобирает.
2. Человек тащит карточку из `backlog` в `todo` — она получает `todo`, `owner`
   самого свободного исполнителя, тот просыпается нарядом сторожа и берёт её в
   `in-progress`.
3. Вторая карточка при тех же условиях уходит следующему по нагрузке.
4. Если у всех исполнителей `in-progress` — дроп отклоняется, карточка остаётся
   в `backlog`, видно сообщение.
5. Человек тащит карточку из `todo` назад — она возвращается в `backlog` без
   владельца, асайна и наряда нет.
6. `bin/test.sh` зелёный (кроме известной сверки с `~/projects/awg`).

## Вне скоупа

- Drag&drop между остальными колонками (`in-progress`, `in-review`, `testing`,
  `ready`, `merged`, `blocked`) — это по-прежнему роли и скрипты.
- Создание рабочего дерева в момент асайна (карточки backlog создаются уже со
  своим деревом — как сейчас).
- Несколько досок/проектов в одном окне, приоритеты и дедлайны.
- Мобильный/тактильный DnD и анимации — только базовая работа мышью и кнопка.
