# Спека 005: Пресеты ролей принадлежат плагину — обновление не ломает сессии

Статус: реализована 02.11.2026 (задачи #062–#063 слиты).

## Зачем

GitHub issue #1: после обновления плагина существующие сессии «слетают» —
становятся стандартными, сторож не может доставлять наряды, сменить пресет
существующей сессии нельзя, и пользователю приходится архивировать и создавать
заново все сессии. На маленьком проекте это терпимо, на инфраструктуре из сотен
вложенных проектов — катастрофа: обновление плагина не должно требовать
пересоздания парка сессий.

## Корень проблемы (подтверждено кодом DSH 0.2.1-rc.3)

1. **Пресет сессии — это её идентификатор в логе.** Заголовок сессии
   (`header.agentPreset`) — факт создания и заморожен; текущий пресет — проекция
   `agentPreset`, которую продвигают события `agent-preset/selected`
   (`dsh-agent-preset-registry/lib/types/session.js`). В логе хранится **id**,
   например `worker`.
2. **При рестарте DSH берёт текущее определение этого id.** Вербатим из
   `dsh-agent-preset-registry/README.md`: «Session logs retain the preset ID and
   blank-session selections; **recovery after restart uses the current definition
   of that ID and rejects a missing definition**». Нет определения — сессия не
   поднимется со своим пресетом; UI показывает её сломанной/стандартной.
3. **Сменить пресет существующей сессии нельзя.** `agentPresets.select()`
   пересобирает только пустую (blank) сессию; для непустой это запрещено на
   уровне API/UI. Поэтому после потери определения остаётся только архив и
   пересоздание — именно то, что описано в issue.
4. **Наши пресеты живут вне плагина.** `bin/install-presets.sh` вставляет 4
   строки `@deepseek-ai/dsh-agent-preset` в `~/.dsh/profiles/<профиль>/cordis.patch.yml`.
   Это ручной профильный патч: обновление/переустановка/сброс профиля, смена
   машины или повторный `install-kanban` без повторного `install-presets` могут
   оставить профиль без строк — id `dispatcher/worker/reviewer/verifier` перестают
   резолвиться, и ломается всё, что завязано на роли (сторож, наряды, доски).
5. **Плагин это может предотвратить:** сервис `agentPresets.register(definition)`
   публичный (реестр DSH), а сам плагин уже грузится в профиль как bundle.
   Значит определения можно регистрировать из кода плагина при каждом старте —
   версия плагина и версия пресетов совпадают, потерять их «обновлением» нельзя.

## Дизайн

1. **Артефакт пресетов в пакете плагина.** `bin/gen-role-presets.sh` продолжает
   собирать `presets/role-presets.patch.yml` (legacy/совместимость) и **дополнительно**
   генерирует `presets/role-presets.json` — массив из 4 определений
   `{ id, name, description, order, plugins }`; YAML-теги `!!js expr` в JSON
   представляются узлами `{ "__jsExpr": "expr" }` (это штатная форма диалекта
   entry-list: загрузчик рекурсивно интерполирует такие узлы).
2. **Самолечение при старте.** Host-половина (`dsh-kanban/lib/index.js`)
   инжектит `agentPresets` и в `apply` регистрирует недостающие определения из
   `presets/role-presets.json`. Ключевое: **дубликаты не считаются ошибкой** —
   `register()` реестра бросает `Duplicate agent preset: <id>`, если профильные
   строки уже зарегистрировались первыми; плагин ловит это и пропускает (legacy
   строки работают как раньше). Если профильных строк нет (их потеряло
   обновление) — плагин регистрирует все четыре, и существующие сессии снова
   открываются: **id в логах сохранены, пересоздание не нужно**. Отмена
   регистрации — через `ctx.effect(() => () => unregister())`, повторный
   эффект Dispose идемпотентен.
3. **Миграция профиля.** `bin/install-presets.sh --takeover` удаляет legacy-блок
   пресетов из профиля (когда плагин их уже поставляет), чтобы в логах не было
   предупреждений о дубликатах; без `--takeover` поведение прежнее (для старых
   версий DSH). В README/KANBAN — раздел «Обновление плагина и пресеты»: гарантия
   стабильных id (`dispatcher/worker/reviewer/verifier`), пресеты едут вместе с
   плагином, повторный `install-presets` для новых установок не нужен.
4. **Защита от повторения.** Правило релиза: id пресетов **никогда не
   переименовываются** (только добавляются новые); при обновлении DSH пресеты
   перегенерируются **в составе плагина** (gen-role-presets → JSON → релиз), а не
   руками в профиле. Это фиксируется в `AGENTS.md` (раздел про обновление DSH) и
   в чеклисте релиза.

## Вне скоупа

- изменение поведения DSH (разрешить смену пресета у непустой сессии) — это
  апстрим DSH, не наш плагин;
- миграция чужих/пользовательских пресетов за пределами четырёх ролей;
- автопереименование пресетов в логах сессий.
